# 存储与传输性能优化（2026-10-17）

本轮延续[采集性能优化](采集性能优化.md)，覆盖原始事件存储、JSON 上传以及 JSON/CSV 下载。测量使用相同的确定性合成数据，先运行本轮修改前的源码副本，再运行优化后的代码。完整结果见[存储与传输性能测量.json](存储与传输性能测量.json)。

## 实现

### 小事件存储

原始记录的压缩尝试阈值从 1,024 字节降至 512 字节，覆盖常见的问卷修改与答案快照。仍使用现有 gzip 存储格式，压缩后连同标头必须节省超过 10% 才采用；小于 512 字节或压缩收益不足的内容直接保存。

事件 hash 继续针对原始 UTF-8 字节计算，预算按逻辑字节计费。现有数据可混合读取，新增写入使用新阈值。旧记录不会在应用启动时重写，现有离线 `compact-evidence` 工具会按新阈值处理记录。

### JSON 上传

原有 `ingest`、`covariates` 的原生 gzip 支持扩展到 `seal`、`reconcile`、`receipts`，以及管理端问卷 `save`、`import`。客户端与服务端共用路由判定，保留原有的 8 KiB 阈值、至少 12.5% 压缩收益要求、1 MiB 解码正文上限、最多 4 个并行解压和 15 秒接收超时。

重试复用同一份已序列化、已压缩的请求，事件、manifest 和 request_id 保持原身份。服务端在分配解压器前按解码长度预占接收预算，实际解码长度必须匹配声明值。缺少原生 CompressionStream 或压缩无收益时，客户端继续发送原文。

### JSON 与 CSV 下载

新增服务端响应压缩：大 JSON 响应按 `Accept-Encoding` 协商 gzip，使用 level 4，阈值为 8 KiB，单个待压缩 JSON 最多 4 MiB。CSV 按流压缩，保持文件读取的背压，不将整份导出读入内存，也不额外保存压缩副本。下载文件名、CSV 的 UTF-8 BOM、原始文件和 manifest 摘要保持一致。

HTTP JSON/CSV 响应最多同时进行 2 个压缩任务，原有回放 actions 接口也使用同一压缩池。名额占满时，接受 identity 的客户端获取原文；只接受 gzip 的请求收到 503。取消下载或文件流出错会关闭相关流并释放名额。响应保留原缓存策略，合并 `Vary: Accept-Encoding`，并移除压缩前的 Content-Length。

图片与 ZIP 使用原有传输，图片原字节和摘要继续用于准备阶段校验。已压缩的轨迹下载不会再次压缩。登录及携带新作答凭据的 reanswer 响应保留原表示；浏览器 IndexedDB 结构继续与旧版冻结运行器兼容。

## 测量

环境为 macOS arm64、Node.js v24.21.0。下表均为正文或有效载荷字节，不含 HTTP 标头、TLS 或真实网络传输时间。

| 场景 | 优化前字节 | 优化后字节 | 减少 |
| --- | ---: | ---: | ---: |
| 1,000 条小问卷事件的存储正文 | 661,564 | 458,921 | 30.63% |
| 5,000 条引用的封存清单上传 | 630,235 | 244,759 | 61.16% |
| 5,000 条引用的对账清单上传 | 630,235 | 244,759 | 61.16% |
| 200 题问卷 JSON 导入上传 | 38,253 | 1,570 | 95.90% |
| 200 题问卷 JSON 响应下载 | 33,283 | 1,510 | 95.46% |
| 10,000 行答案 CSV 下载 | 664,534 | 257,235 | 61.29% |

小事件写入独立、单列的 SQLite 表并完成 WAL checkpoint 后，文件从 692,224 字节减至 520,192 字节，减少 24.85%。该数字只用于比较编码后记录的页占用，不代表完整业务数据库缩小比例。已有的大交互记录压缩结果不变。

压缩需要 CPU：本机小事件编码中位数约 0.0135 ms/条；630,235 字节清单的原生接口压缩准备约 7.7 ms；664,534 字节 CSV 的本机处理与编码中位耗时由 2.20 ms 增至 8.71 ms。JSON 上传使用 Node 的原生 CompressionStream 测量，浏览器实际 CPU 耗时需在目标设备上测量。下载测量通过 Fastify inject 执行真实压缩和流读取，未经过实际 HTTP socket。

另以真实 LabStore 接收路径复测，在 4,096 条历史记录、每批 16 条时，问卷批次中位耗时为 7.722 ms，交互诊断为 7.852 ms；历史字节扫描保持为零，仅对每条新记录统计逻辑字节。本轮新增小事件压缩有相应的编码、解码成本，完整时延分布保留在测量文件中。

## 复现与验证

```sh
npm run profile:transfer-storage -- .local/transfer-storage-profile.json
npm run profile:ingestion -- .local/ingestion-profile.json
npm run check
```

测量脚本使用临时数据库和合成数据，完成后清理。原始事件解码、压缩上传回显、JSON/CSV 下载解码均验证与原字节相同。

新增回归覆盖小事件压缩、扩展上传路由及长度限制、下载编码权重与拒绝、并发压缩限制、CSV 取消和读故障、文件流与名额释放。原有采集、备份恢复、封存与旧冻结版本测试继续适用。

类型检查、生产构建、SQLite 冒烟检查，以及 187 项单元、68 项端到端浏览器、16 项运行器浏览器、4 项逻辑集成测试全部通过。统一回放压缩池后，响应压缩单元测试及下载/回放的两项定向浏览器回归也通过。
