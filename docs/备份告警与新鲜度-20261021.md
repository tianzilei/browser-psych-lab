# 备份失败与新鲜度告警

2026-10-21。为全量备份、SQLite 快照和应用服务增加 systemd 失败钩子、每日新鲜度/磁盘/基准检查及本地告警记录。

## 检查项

`psychlab-backup-monitor.mjs` 每日 09:00 运行，检查：

| 检查 | 通过条件 |
| --- | --- |
| 数据库可读 | 主库可打开并计算数据指纹 |
| 全量 bundle | 最新 READY BACKUP 的目录和 manifest 存在 |
| 全量 sidecar | sidecar 的 job_id 与最新 READY 一致 |
| 全量新鲜度 | 数据指纹未变，或 sidecar 年龄不超过 `BACKUP_FULL_MAX_AGE_HOURS`（默认 192 小时） |
| SQLite 快照 | sidecar、`.sqlite.zst`、`.json` 元数据存在 |
| 快照哈希 | `.sha256` 与文件实际 SHA-256 一致 |
| 快照新鲜度 | 数据指纹未变，或 sidecar 年龄不超过 `BACKUP_SNAPSHOT_MAX_AGE_HOURS`（默认 120 小时） |
| 基准指针 | `.base-bundle.json` 与最新快照元数据一致 |
| 基准兼容 | 当前 assets/runners 被基准 bundle 覆盖 |
| Timer 状态 | full 与 snapshot timer 均为 active + enabled |
| Service 失败 | backup 与 sqlite-snapshot service 均不是 failed |
| 磁盘 | 可用空间不低于 `BACKUP_MIN_FREE_GB`（默认 8）且不低于 `BACKUP_MIN_FREE_PERCENT`（默认 20%） |

“数据指纹未变”时允许 bundle 较旧，因为 Wrapper 会主动跳过无变化周；不会把“没有新数据”误报为“备份失败”。

## 告警路径

- 状态文件：`/var/lib/browser-psych-lab/backup-status.json`（`600 psychlab`）
- 本地告警目录：`/var/lib/browser-psych-lab/alerts/`（`700 psychlab`）
  - 每次失败写入一个 `<UTC 时间>-<unit>.json`（`600`）
  - 追加 `alerts.log`（`600`）
- systemd `OnFailure` 已加到：
  - `browser-psych-lab.service`
  - `browser-psych-lab-backup.service`
  - `browser-psych-lab-sqlite-snapshot.service`
  - `browser-psych-lab-backup-monitor.service`
- 告警模板：`browser-psych-lab-alert@.service`
- 监控 timer：`browser-psych-lab-backup-monitor.timer`，每日 09:00，`Persistent=true`

失败示例：

```text
/var/lib/browser-psych-lab/alerts/20261021-012520-browser-psych-lab-backup-monitor.service.json
```

告警 JSON 包含 unit、ActiveState、Result、ExecMainStatus，以及 monitor 的完整 `backup-status.json`（不含受试者数据）。

## 本地告警使用方式（当前定稿）

已确定**先只用本地告警**，`BACKUP_ALERT_WEBHOOK`、`BACKUP_HEALTHCHECK_URL`、`BACKUP_ALERT_HEALTHCHECK_FAIL_URL` 保持为空。不会向任何外部服务发送数据。

日常检查：

```bash
# 最近一次失败告警（如有）
sudo cat /var/lib/browser-psych-lab/alerts/latest.json
sudo cat /var/lib/browser-psych-lab/alerts/alerts.log

# 最近一次 monitor 的全部检查结果
sudo cat /var/lib/browser-psych-lab/backup-status.json

# systemd 层失败与定时器
systemctl --failed
systemctl list-timers 'browser-psych-lab-*'
```

告警文件按时间累积在 `/var/lib/browser-psych-lab/alerts/`；`latest.json` 始终指向最近一次失败。处理完告警后可手动删除 `latest.json`，`alerts.log` 可按需清空。

**边界**：没有外部推送，也没有死人开关。若 monitor timer 被停用或服务器长期无人登录，本地告警不会被主动送出；外部发现需要后续配置 Healthchecks/Webhook。
