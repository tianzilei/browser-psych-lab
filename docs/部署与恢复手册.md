# 部署、备份和恢复

> 并发、准入和容量口径已于 2026-10-11 同步。完整预算、默认 2／1 与特定 ECS 7／7 的区别见 [并发设计与容量验收](并发设计与容量验收.md)。

## 初始部署

更新日期：2026-10-11。部署按实际主机、网络与研究负载选择任务／准备上限；源码与环境示例默认 2／1，[已有 ECS 代表负载](ecs-capacity-and-idle.md)记录采用 7／7。早期 2c4g／1c2g、1Mbps 方案属于历史试运行配置，不能替代现行容量验收。部署时记录实际本地文件系统、挂载和设备支持矩阵。使用 Node 24.21.0、npm 11.19.0，在完整构建环境按 lock 安装并构建，执行 `npm run check`；然后在发行目录用相同 lock 执行 `npm ci --omit=dev`。保留构建后的 `dist/release.json`、全部 `dist/web`（含 `runner-contract.json`、压缩副本）、`dist/server`、package/lock、部署配置及版本对应运行器；活跃 SQLite/WAL/shm 放本地文件系统。

创建专用 `psychlab` 用户，私有目录 `/var/lib/browser-psych-lab` 和独立备份挂载，目录 0700，文件 0600；父目录不得被普通其他用户写入。检查 hard link 排他发布、文件 sync 与目录 sync 的实际平台能力。不得把 research-assets/exports/backups 配成公网静态目录。

1. 复制 `deploy/production.env.example` 到受保护的 `/etc/browser-psych-lab.env`，填写实际 PUBLIC_ORIGIN、存储/DB/备份路径和管理员密码哈希。环境文件不要提交到 Git。
2. 在构建环境用 `npm run auth:setup` 生成唯一的 `ADMIN_PASSWORD_HASH` 并从项目 .env 复制到部署环境文件；命令不打印明文。生产初始化数据库目录由应用完成；没有密码配置时登录拒绝。
3. 修改 `deploy/browser-psych-lab.service` 的 Node/发行目录/写路径。2c4g 模板设置 `MemoryMax=1536M`、`UV_THREADPOOL_SIZE=2`；1c2g 可使用 [可选 drop-in](../deploy/1c2g.conf) 的 1024M/1 作为试运行起点。在实际压力测量中检查 RSS 和 OOM，不能把上限当作内存用量预测。单实例启动；同一 DB 的第二应用会被拒绝。应用仅监听 127.0.0.1。
4. 配置现有 HTTPS 入口，或修改仓库 Caddy/nginx 模板的域名、证书和代理路径，选择一个反代。同源网页/API；反代透传应用协商的编码，不额外压缩、改图或缓存私有响应。应用仅信任 loopback 代理的转发地址。
5. 检查 `/api/health/live` 和 `/api/health/ready`，登录 `/admin.html`，跑代表性 TEST_ONLY 研究并验证下载、导出、封存与中断。

模板没有自动安装到系统。本机流程测试不能证明模板在另一台 Linux 主机已部署成功。

## 任务准入、图片准备与请求预算

在受保护的服务环境文件设置 `SESSION_CONCURRENCY` 和 `PREPARATION_CONCURRENCY`，两者接受整数 1–10000，默认分别为 2 和 1。先采用与主机相符的保守起点，再按代表负载测试确定运行上限；配置范围不代表验收容量。修改后重启单应用实例，不能启动第二应用连接同一数据库扩容。

含任务组的整份答卷从进入作答开始计入跨研究全局任务名额，纯问卷不占这类名额。任务满额返回 `SESSION_CAPACITY_FULL`，准备满额返回 `PREPARATION_CAPACITY_FULL`，均为 HTTP 409、`Retry-After: 1800`，界面建议约 30 分钟后重试；没有等待队列、序位或自动放行。正常完成／终止释放任务名额；未关闭 `ISSUED` permit 保持占位，不能仅凭普通租约过期判断运行已结束。降低配置保留已有有效占位，超额期间拒绝新增任务。

图片准备单独限制活动会话数，每个会话仍只有一个在途图片流，逐张下载原字节、核对摘要／尺寸并实际解码。准备页显示下载百分比，可取消；精确 nonce 释放，真实流退出前保留占用。活动准备每 20 秒续票，票据闲置 90 秒且无流时由后续扫描清理，20 分钟硬期限取消；浏览器本组准备预算 20 分钟，单图 60 秒无进展失败。准备票据在内存中，重启后重新准备；任务占位、原始记录和许可在 SQLite 中持久保存。

新冻结固定刺激和评分任务统一声明 `idle120-offline300-v1`：120 秒无实际操作中断，每 60 秒一个小型 activity 请求，单次超时 10 秒；300 秒无法确认活动即中断。服务端每 30 秒扫描，连续 300 秒无续活时终止会话、关闭未知许可并释放名额。activity 后台发送，刺激循环不等待下载、上传或封存。问卷／准备阶段另有每分钟准入续活，纯问卷不使用任务空闲中断。

旧冻结运行器保留原代码／摘要／客户端超时。无准备能力声明的旧图片 GET 仍在 Cookie／资源引用鉴权后使用同一准备容量，满额立即拒绝；新能力运行器必须提供票据和 writer headers。当前服务端不提供旧版 18 秒等位或新版 45 分钟排队，不能手改归档声明迁移已有会话。

正式非 GET 接收预算为 32 个／20 MiB，gzip 解压最多 4 个并发；DB 在途＋等待为 32 个／2 MiB，预留 4 个请求容量给控制操作，单 RPC 在途。临时背压返回 503，频次超限返回 429；容量 409 不自动重试。完整生命周期、预算、版本兼容与验收方法见 [并发设计与容量验收](并发设计与容量验收.md)。

若部署使用 1Mbps，它是全服务共享的公网预算。公共代码、问卷、ACK、管理预览和文件下载均占带宽；增加准备数不能增加总带宽。采集高峰错开大文件导出／备份下载和集中预览，备份作业仍按 RPO 安排。用实际每组原图字节量及目标主机测量决定上限，IOPS／标称吞吐不能替代 FULL 提交尾延迟证据。

## 研究使用

在本地编写问卷 JSON→管理端上传并校验 JSON/图片 ZIP→生成模拟问卷检查→生成冻结版本→开放新接入。后续修改只生成新版本，既有会话保持原版本。分组任务使用多个组；全任务连续模式使用单组。默认新图片组 K=2。

发布和开放接入是独立操作。暂停新接入不影响已有凭据补传、组结束和封存。质量页面显示服务端最后接收时间，不把 ACTIVE 当作“正在连接”。人工备注/排除标记另建追加修订，不改原始答案或系统诊断。

正式采集前，管理员登记真实环境档案，字段包括 hardware、filesystem、device_matrix、capacity_report、independent_restore_report、backup_target、rpo、rto、operator、verified_at、backup_job_id、restore_manifest_hash、restore_verified:true。选择该环境开放正式 gate。档案不可覆盖，修订用新 environment_id；正式版本预算里的 environment_id 必须与 gate 匹配。

## 日常监测和定期备份

管理主页的“服务器存储”卡片显示数据所在磁盘的已用百分比、已用／总容量和服务进程可用容量。百分比使用物理占用 `(blocks-bfree)/blocks`，可用容量使用 `bavail*bsize`，因此预留空间可能使已用与可用之和小于总量。统计包含该文件系统上的系统文件、问卷、资源及同盘备份，并非仅数据库文件；不递归扫描研究目录。登录后读取，可见页面每分钟刷新，也可点“刷新存储”；更新失败保留上次成功数值与时间。刷新只更新存储卡片，保留未保存的改名文字和上传文件选择；退出登录取消轮询。存储处理继续由管理员按备份／维护流程执行，卡片不自动删除数据。

管理员通过 `/api/lab/operations` 查看 writer 的 queued/in_flight/bytes/ready、`state.admission` 的 limited_active/unlimited_active/limit/pinned/over_limit、准备 active/streams/limit、维护 busy、WAL 字节、空闲磁盘、session/disposition、未关闭 permit 和最近 READY 备份。admission.active 包含纯问卷，任务占用看 limited_active；任务／准备 queued 固定为 0，writer.queued 才是等待处理的数据库请求数。分别监测容量 409、临时背压 503 和频次 429，以及 pending/quarantine、未决作业、WAL、磁盘余量和恢复点落后；阈值按正式容量报告设置。公开健康 API 不包含凭据或研究数据。

管理员使用同一登录凭据调用备份 API，或执行：

```sh
BACKUP_API_ORIGIN=http://127.0.0.1:3000 \
PUBLIC_ORIGIN=https://实际域名 \
BACKUP_PASSWORD_FILE=/受保护目录/管理密码文件 \
npm run backup
```

密码文件 0600，含明文管理密码，仅用于自动化登录；不要传命令行明文密码。按实际 RPO 调整 `deploy/browser-psych-lab-backup.timer`，检查 timer/service 失败记录并定期执行恢复演练。

备份流程：持久登记作业/资源屏障→SQLite Online Backup 完成→核查目的库 integrity/FK→从**目的库**读取全部 READY 资产和运行器→持久 pin/释放屏障→复制全部实际文件→核验内容身份/摘要→如配置独立目标，复制并再核验→READY→释放 pin。原始采集写入不受资源屏障阻止。独立目标不得与活跃根在同一 filesystem；额外确认实际物理独立性与访问权限。

本机备份可得到 READY，但标注 independent:false，只用于开发恢复，不能支撑正式 gate。备份数据库文件包含参加者访问凭据，下载仅管理员可用；恢复不包含明文管理员密码/环境秘密，另行配置。保留周期由研究策略确定，代码没有自动按年龄删除备份或原始数据。

单盘 ECS 需要把本机包作为日常备份、再由管理员下载并异地留存时，显式设置 `BACKUP_LOCAL_ONLY=1` 并清空 `BACKUP_ROOT`。该模式不尝试独立副本，作业结果为 `local_only:true`、`independent:false`，manifest 的 `backup_scope` 为 `local-only`；因此不能声明独立恢复，也不能支撑正式 gate。未设置该标志时，`BACKUP_ROOT` 与活跃根同文件系统仍按 `BACKUP_TARGET_SAME_FILESYSTEM` 拒绝，避免把同盘副本误当独立备份。每日 timer 由 `deploy/browser-psych-lab-backup.timer` 安装；首次运行前必须创建 `/etc/browser-psych-lab-backup-password`（0600，内容为管理密码）。

## 作业中断和重建

资源变更作业失败／超时或服务进程中断后，未决作业变为 RECOVERY_REQUIRED，屏障/pin 不依靠时间失效。先暂停新接入，核查磁盘和 worker 是否实际退出。通过作业恢复 API 提交核查报告并执行文件核验，系统保存 inventory/hash 和报告，旧作业记 FAILED，再释放已验证的 pin/barrier。失败文件保持不变。未引用资源需显式“维护删除”，包括该资产的临时文件。

导出只读取数据库并生成私有派生文件，不持有资源屏障或 pin。导出 worker 报错／超时后，系统先等待其退出，再将作业记为 FAILED，允许后续导出；部分 CSV 保留在旧作业目录且不可下载，重试生成新作业。服务进程整体中断留下的未决作业仍须按恢复流程核查。

派生重建需要管理员权限、研究已暂停且没有 ISSUED permit。重放单读视图并发布新的 generation，源事件、raw、seal、diagnostic、问题标记不覆盖。失败保留原 generation。源证据不完整不能通过重建补造；终止历史在 CSV 中按 historical 标识并保留缺项/重放错误。

CSV 的单个 `table,data_json` 文件保留表类型和结构，可用 Python csv+json 或 R 读取；配套 manifest 记录实际读视图时点、snapshot/source/csv 摘要与行数。原始 UTF-8 在 raw_utf8 字段，软件结果在 trial_results 行；planned target、audit、actual gap、input time/RT 与许可计划都可追溯。问题标记不会自动删掉试次。

每次导出将完整证据、问卷结果和轨迹三个 CSV 计入同一预算：合计最多 1 GiB、200 万行，物化写入最多 90 秒；维护 worker 总超时仍为 120 秒。逐行写盘，源数据在同一个数据库读视图内读取。超限返回 HTTP 413（EXPORT_BUDGET_EXCEEDED 或 EXPORT_ROW_BUDGET_EXCEEDED），不会截断文件并宣称导出完成。

管理页“导出问卷结果”使用 `format: answers`，生成 `answers.csv`、`preparations.csv` 和清单，只读取各会话的冻结问卷、设备准备记录与已封存页面快照，不扫描或展开操作轨迹，也不生成原始证据 CSV。“下载数据”保留全量证据导出。接口省略 format 时仍按全量导出处理；页面展示答案、完整证据和导出说明的可用链接。

答案 CSV 每个会话一行，题目／量表轴分列，列头包含题号和题干。基础信息包含会话 ID、问卷版本、完成状态、创建时间、同意时间、最后接收时间和时区；日期采用 `YYYY-MM-DD HH:mm:ss.SSS`，固定为北京时间 `Asia/Shanghai`。数值、标签及未确认／跳题等状态分列，多选、文本和单选保留精确 JSON 值列。不同版本取题目／轴的并集，不存在的题标记 NOT_IN_VERSION；列字典与版本定义保存在清单的 answer_columns。未开始、中断和未完成会话也保留各自一行。原始证据的时间戳保持原值。旧导出文件保持原格式，管理页识别旧缓存后生成新格式答案文件。

管理页的问卷下载文件按 `问卷名_YYYY-MM-DD_HH-mm-ss.扩展名` 命名，时间为实际下载请求时的北京时间。适用于答卷 CSV、完整数据 CSV、导出说明和问卷 JSON；再次下载历史导出时使用当前管理名称和本次下载时间。下载名替换路径／控制字符，并限制 UTF-8 长度；中文通过响应头的 UTF-8 文件名传递。服务器内部文件、导出清单引用及内容哈希保持原值。

独立轨迹 CSV 下载通道已关闭：管理页没有“导出轨迹”按钮或轨迹文件链接，已登录管理员访问任何就绪作业的 `trajectories.csv`（包括历史链接）均返回 HTTP 410／TRAJECTORY_DOWNLOAD_DISABLED，未登录请求仍先拒绝鉴权。私有文件下载层同时拒绝该文件。历史原始记录、完整证据下载和在线回放保留。

如研究确认交互轨迹不再需要，可用 `npm run purge:trajectories -- --study "<问卷标题>" --apply` 清理指定问卷的 `INPUT_DIAGNOSTIC` 作用域。命令默认只打印计划；`--apply` 先做在线数据库备份和完整性检查，再在一个事务内临时移除删除保护触发器，只删除整段交互轨迹及其 disposition、scope usage、replay index，重建派生索引标记并写 `lab_audit`。页面修订、页面快照、`lab_seals`、同意、协变量和答案不删除；混合页面/轨迹作用域或仍有非终态会话时拒绝执行。清理报告和 `before.sqlite` 保存在 `STORAGE_ROOT/trajectory-purge-<UTC 时间>/`，应下载留存。该操作不可撤销，执行前确认轨迹确无分析用途。

管理页不提供问卷删除入口，`POST /api/lab/studies/:study/delete` 对已登录管理员返回 403／QUESTIONNAIRE_DELETION_DISABLED，已有问卷、版本和答卷继续保留。可通过“隐藏问卷”暂停新接入。

具有有效界面快照的答卷可单独下载 `/api/lab/sessions/:session/trajectory.json.gz` 或 `/api/lab/sessions/:session/replay.html`；均要求管理员登录，没有可回放快照时返回 404。文件名使用 `问卷名_会话前8位_北京时间.扩展名`。HTML 包含原始压缩轨迹、播放器及引用图片，离线打开时校验原文和图片摘要，无需视频编码服务。

发布时构建 `dist/server/offline/offline-replay.js` 并随服务一同部署。`lab_replay_index` 是可重建的派生索引，只用于筛选和统计；按 `lab_events` 最新行号校验版本标记。大库首次升级可在停止服务后预建索引，避免占用启动 RPC 时间。此索引不覆盖原始事件或处理历史。

服务器临时文件在 `STORAGE_ROOT/research-recording-downloads/<UUID>/`，正常下载完成、断开和生成失败均立即清理。安装 `deploy/browser-psych-lab-recording-cleanup.service`、`.timer`，预先创建此目录并授权服务用户；执行 `systemctl enable --now browser-psych-lab-recording-cleanup.timer`。清理任务每天北京时间 00:00 运行，仅移除该目录内超过一小时的 UUID 子目录，不跟随符号链接，不触碰原始轨迹、图片或备份。服务限制 CPU 为 10%、内存为 128 MiB；没有常驻编码进程或视频缓存。

## 完整恢复

在隔离主机／独立新目录操作，先停止要恢复的应用。恢复目标目录必须不存在，不覆盖活跃数据。

```sh
npm run build
npm run restore -- /独立备份挂载/作业ID /新的私有存储根
```

恢复 CLI 先核验所有清单路径、文件摘要、SQLite integrity/FK、READY 资产引用及运行器存在，再排他复制数据与资源。目的库 gate 固定 CLOSED，旧管理 Cookie 失效，未决维护作业改为 RECOVERY_REQUIRED，未关闭运行保留 ISSUED，不能推断已正常结束。启动后新策略任务按失联扫描或恢复页面关闭 UNKNOWN；旧策略按原合同明确结束未知运行。历史等待条目退为 LEFT，图片准备重新取得票据。输出 `restore-report.json` 的 backup_manifest_hash 用于环境档案；不要把报告里的“文件核查成功”当作恢复业务演练通过。

配置 DATABASE_PATH 指向新根下 `database/browser-psych-lab.sqlite`、STORAGE_ROOT 指向新根，使用锁定依赖/相应发行物启动，重新配置管理员密码/HTTPS。核验会话数量、原始摘要、完成/终止凭证、版本代码、全部图片、私有访问、CSV 和未知运行。按维护流程结束备份库中的未决任务，测量实际 RPO/RTO。记录设备/容量/独立恢复证据后，创建新环境档案并开放对应正式 gate。

如果恢复校验失败，目的目录不得用于采集；保留失败产物用于核查，修正备份来源后换新目录重新恢复。升级前同样先备份/恢复演练。数据库 schema 不支持降级运行；不要用旧服务覆盖已升级库。首版追加 schema 保留全部原始历史，版本升级通过新的发行目录和已留存的 frozen runner 过渡。
