# 部署、备份和恢复

## 初始部署

用户指定阿里云 Ubuntu 26.04、系统盘 2120 IOPS / 106.0 MB/s、1Mbps 公网带宽，原 2c4g 配置正在评估降至 1c2g；当前最多同时 1–2 例，其余 FIFO 等待。部署时记录实际本地文件系统、挂载和设备支持矩阵。使用 Node 24.21.0、npm 11.19.0，在完整构建环境按 lock 安装并构建，执行 `npm run check`；然后在发行目录用相同 lock 执行 `npm ci --omit=dev`。保留构建后的 `dist/release.json`、全部 `dist/web`（含 `runner-contract.json`、压缩副本）、`dist/server`、package/lock、部署配置及版本对应运行器；活跃 SQLite/WAL/shm 放本地文件系统。

创建专用 `psychlab` 用户，私有目录 `/var/lib/browser-psych-lab` 和独立备份挂载，目录 0700，文件 0600；父目录不得被普通其他用户写入。检查 hard link 排他发布、文件 sync 与目录 sync 的实际平台能力。不得把 research-assets/exports/backups 配成公网静态目录。

1. 复制 `deploy/production.env.example` 到受保护的 `/etc/browser-psych-lab.env`，填写实际 PUBLIC_ORIGIN、存储/DB/备份路径和管理员密码哈希。环境文件不要提交到 Git。
2. 在构建环境用 `npm run auth:setup` 生成唯一的 `ADMIN_PASSWORD_HASH` 并从项目 .env 复制到部署环境文件；命令不打印明文。生产初始化数据库目录由应用完成；没有密码配置时登录拒绝。
3. 修改 `deploy/browser-psych-lab.service` 的 Node/发行目录/写路径。2c4g 模板设置 `MemoryMax=1536M`、`UV_THREADPOOL_SIZE=2`；1c2g 可使用 [可选 drop-in](../deploy/1c2g.conf) 的 1024M/1 作为试运行起点。在实际压力测量中检查 RSS 和 OOM，不能把上限当作内存用量预测。单实例启动；同一 DB 的第二应用会被拒绝。应用仅监听 127.0.0.1。
4. 修改 nginx 域名、证书和代理路径。启用 HTTPS，同源网页/API；私有流不压缩、不改图、不缓存。应用仅信任 loopback 代理的转发地址。
5. 检查 `/api/health/live` 和 `/api/health/ready`，登录 `/admin.html`，跑代表性 TEST_ONLY 研究并验证下载、导出、封存与中断。

模板没有自动安装到系统。本机流程测试不能证明模板在另一台 Linux 主机已部署成功。

## 整例准入与 1Mbps 准备

`SESSION_CONCURRENCY=2` 默认双例，只接受 1 或 2；1c2g 首次试运行可设为 1。全局会话队列跨研究合计最多 64 个活动/等待条目，等待页不显示问卷、不领取 writer/permit，服务端同样拒绝直接开始。正常完成或明确终止释放名额；无 ISSUED 的失联会话 5 分钟后回收，刷新在有效租约内保留次序，主动退出后重排到队尾。ISSUED 持续占位，恢复须明确关闭 UNKNOWN。会话 FIFO 存于 SQLite，随重启/备份恢复保留；原始记录和冻结版本不改。完整规则和部署配置见 [会话排队与小规格部署](会话排队与小规格部署.md)。

会话等待队首约 3 秒、其他约 10 秒查询，活动每分钟续租，并合并租约写入；计时组前停止并等在途请求结束，许可负责组内占位。降低并行配置不强制终止既有例次，已有占位超额时停止新放行直到自然回落。

保持 `PREPARATION_CONCURRENCY=1`，可配置范围 1–4；当前 1Mbps 目标使用 1。图片准备队列最多 64 个票据，FIFO 放行一个会话，本会话串行下载、校验和解码图片。准备页显示队列位置和字节进度，可取消；只有 HTTP 流实际结束或断开后才回收图片流名额。图片票据轮询不写 SQLite，准备期间每分钟续期方案/写者；进入计时组前关闭续期和全部队列轮询。

新运行器的图片准备排队预算 45 分钟，本组准备预算 20 分钟；图片连续 60 秒无字节进展失败。它们是有限失败预算，并非吞吐或准入保证。离开页面尽力释放，异常断连由流关闭、空闲租约和硬期限清理。图片准备队列只在内存中，服务重启后需要重新准备；整例 FIFO 保存在 SQLite，既有原始记录、分配及未知许可仍遵守持久合同。暂停新接入不会取消已有队列和补传。

旧冻结运行器代码及摘要保持原样。只有其 canonical 清单没有队列能力声明时才允许原图片 GET，仍须 Cookie/冻结版本引用鉴权，并共享 FIFO 下载容量。旧客户端原 20 秒超时保留，服务端排队最多等 18 秒；大图片或长队列需要发布新版本，让新参与者使用新准备机制。新发行物的 `runner-contract.json` 纳入运行器摘要，无票据 GET 被拒绝；不得手改归档声明或旧冻结数据。升级回归及预算详见 [阿里云 1Mbps 部署与验证](阿里云1Mbps部署与验证.md)。

1Mbps 为共享公网预算，图片排队不限制整个服务的出站字节。公共代码、问卷、ACK、管理预览和文件下载仍占带宽。采集高峰暂停大文件导出/备份**下载**与集中预览；备份作业按 RPO 安排，不能为错峰取消所需备份。把首批实际每组原图总量代入预算并在目标主机测试，不以 2120 IOPS 或 106 MB/s 推断 FULL 提交延迟或单例/双例可用容量。

## 研究使用

在本地编写问卷 JSON→管理端上传并校验 JSON/图片 ZIP→生成模拟问卷检查→生成冻结版本→开放新接入。后续修改只生成新版本，既有会话保持原版本。分组任务使用多个组；全任务连续模式使用单组。默认新图片组 K=2。

发布和开放接入是独立操作。暂停新接入不影响已有凭据补传、组结束和封存。质量页面显示服务端最后接收时间，不把 ACTIVE 当作“正在连接”。人工备注/排除标记另建追加修订，不改原始答案或系统诊断。

正式采集前，管理员登记真实环境档案，字段包括 hardware、filesystem、device_matrix、capacity_report、independent_restore_report、backup_target、rpo、rto、operator、verified_at、backup_job_id、restore_manifest_hash、restore_verified:true。选择该环境开放正式 gate。档案不可覆盖，修订用新 environment_id；正式版本预算里的 environment_id 必须与 gate 匹配。

## 日常监测和定期备份

管理员通过 `/api/lab/operations` 查看 writer 数量/字节队列、`state.admission` 的 active/queued/limit/capacity/pinned/over_limit、图片准备的 active/queued/streams/limit/capacity、维护任务、WAL 字节、空闲磁盘、session/disposition 数量、未关闭 permit、最近 READY 备份。关注 REQUEST/QUEUE/RATE/Maintenance 拒绝、pending/quarantine 的增长、未关闭 permit、未决作业、WAL 增长、磁盘余量和恢复点落后；阈值按正式容量报告设置。公开健康 API 不包含凭据或研究数据。

管理员使用同一登录凭据调用备份 API，或执行：

```sh
BACKUP_API_ORIGIN=http://127.0.0.1:3000 \
PUBLIC_ORIGIN=https://实际域名 \
BACKUP_PASSWORD_FILE=/受保护目录/管理密码文件 \
npm run backup
```

密码文件 0600，含明文管理密码，仅用于自动化登录；不要传命令行明文密码。按实际 RPO 调整 `deploy/browser-psych-lab-backup.timer`，检查 timer/service 失败记录并定期执行恢复演练。

备份流程：持久登记作业/资源屏障→SQLite Online Backup 完成→核查目的库 integrity/FK→从**目的库**读取全部 READY 资产和运行器→持久 pin/释放屏障→复制全部实际文件→核验内容身份/摘要→如配置独立目标，复制并再核验→READY→释放 pin。原始采集写入不受资源屏障阻止。独立目标不得与活跃根在同一 filesystem；额外确认实际物理独立性与访问权限。

本机备份可得到 READY，但标注 independent:false，只用于开发恢复，不能支撑正式 gate。备份数据库文件包含参加者访问凭据，下载仅管理员可用；恢复不包含明文管理员密码/环境秘密，另行配置。保留周期由研究策略确定，代码没有自动按年龄删除备份或原始数据。

## 作业中断和重建

作业超时/进程中断变为 RECOVERY_REQUIRED，屏障/pin 不依靠时间失效。先暂停新接入，核查磁盘和 worker 是否实际退出。通过作业恢复 API 提交核查报告并执行文件核验，系统保存 inventory/hash 和报告，旧作业记 FAILED，再释放已验证的 pin/barrier。失败文件保持不变。未引用资源需显式“维护删除”，包括该资产的临时文件。

派生重建需要管理员权限、研究已暂停且没有 ISSUED permit。重放单读视图并发布新的 generation，源事件、raw、seal、diagnostic、问题标记不覆盖。失败保留原 generation。源证据不完整不能通过重建补造；终止历史在 CSV 中按 historical 标识并保留缺项/重放错误。

CSV 的单个 `table,data_json` 文件保留表类型和结构，可用 Python csv+json 或 R 读取；配套 manifest 记录实际读视图时点、snapshot/source/csv 摘要与行数。原始 UTF-8 在 raw_utf8 字段，软件结果在 trial_results 行；planned target、audit、actual gap、input time/RT 与许可计划都可追溯。问题标记不会自动删掉试次。

## 完整恢复

在隔离主机／独立新目录操作，先停止要恢复的应用。恢复目标目录必须不存在，不覆盖活跃数据。

```sh
npm run build
npm run restore -- /独立备份挂载/作业ID /新的私有存储根
```

恢复 CLI 先核验所有清单路径、文件摘要、SQLite integrity/FK、READY 资产引用及运行器存在，再排他复制数据与资源。目的库 gate 固定 CLOSED，旧管理 Cookie 失效，未决维护作业改为 RECOVERY_REQUIRED，未关闭运行仍保留 ISSUED，待参加者明确关闭 UNKNOWN。输出 `restore-report.json` 的 backup_manifest_hash 用于环境档案；不要把报告里的“文件核查成功”当作恢复业务演练通过。

配置 DATABASE_PATH 指向新根下 `database/browser-psych-lab.sqlite`、STORAGE_ROOT 指向新根，使用锁定依赖/相应发行物启动，重新配置管理员密码/HTTPS。核验会话数量、原始摘要、完成/终止凭证、版本代码、全部图片、私有访问、CSV 和未知运行。按维护流程结束备份库中的未决任务，测量实际 RPO/RTO。记录设备/容量/独立恢复证据后，创建新环境档案并开放对应正式 gate。

如果恢复校验失败，目的目录不得用于采集；保留失败产物用于核查，修正备份来源后换新目录重新恢复。升级前同样先备份/恢复演练。数据库 schema 不支持降级运行；不要用旧服务覆盖已升级库。首版追加 schema 保留全部原始历史，版本升级通过新的发行目录和已留存的 frozen runner 过渡。
