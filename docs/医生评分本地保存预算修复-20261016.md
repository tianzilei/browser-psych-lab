# 医生评分本地保存预算修复

2026-10-16。受试者在手机微信和手机浏览器准备“医生第一印象评分”时，出现“本地事务耗时超过此版本预算，无法开始该组”。

## 原因

原最新版本 `5502863b-b0d3-456b-9783-e18e067b770f` 的 `budget.commit_ms` 为 40。浏览器准备阶段执行 10 轮本地存储测试，每轮连续完成 4 次包含编码、摘要、events/outbox/meta 三表写入和严格持久化的保存路径，取整轮最大耗时与 40 毫秒比较。该提示出现在发放运行许可之前。

评分任务由受试者提交评分后推进。冻结评分运行器会等待答案本地保存及下一张开始意图保存，并执行既有的 3 秒图片间隔。该流程与固定呈现、动态补测任务的下一刺激提交截止点不同，40 毫秒的整轮准入门槛过严。

## 修复范围

仅将该问卷源 JSON 的 `budget.commit_ms` 显式设置为 1000，按标准导入流程生成新冻结版本，并沿用原冻结运行器 `a1dd15e39bf7494e22e5fc0865221233a2e807c126dab62e3fd157acd706010c`。运行器文件、评分项目、照片、每类抽取 8 张共 32 张的规则、知情同意、轨迹开关及 3 秒间隔保持原值。

1000 毫秒是准备检查的允许预算；不会为每次点击额外增加 1 秒等待。服务器仍校验实际检查耗时，严格本地保存、摘要和封存流程继续生效。旧冻结版本及既有会话保留原值，受试者需要使用新版本入口。

## 验证

在同一服务器建立独立数据库与资源副本，只复制问卷和资源，不复制受试者或凭据。使用生产部署代码及原冻结运行器，通过 SSH 隧道运行 Chromium 手机尺寸与触控仿真。

给每次摘要调用额外增加 25 毫秒异步延迟，旧 40 毫秒版本复现原提示，未申请运行许可。新预算版本相同条件下 10 轮准备测量最大约 113.4 毫秒，成功进入评分。

完整 32 张测试已到达“研究已完成，数据已保存”。浏览器核对 224 个评分值一致、outbox 为 0、无页面脚本错误。上传有一次临时 HTTP 503，原客户端重试后完成；原浏览器脚本在“所有 HTTP 请求必须无错误”的额外断言处失败，原报告保留。随后通过独立只读核查确认：32 张共 224 个值一致、550 条原始记录的解压后 SHA-256 一致、组内事件全部 ACCEPTED、哈希链与精确封存清单匹配、permit 为 CLOSED_NORMAL、会话为 COMPLETED。实际最短图片间隔为 3015.6 毫秒。

此测试覆盖模拟保存延迟与手机视口，未直接运行真实微信或手机硬件。

验证脚本和报告保存在本机 `.local/doctor-storage-budget-20261016/`，服务器隔离目录为 `/var/lib/browser-psych-lab/doctor-storage-budget-20261016/`。
