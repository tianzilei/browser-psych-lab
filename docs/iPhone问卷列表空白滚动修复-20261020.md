# iPhone 问卷列表空白滚动修复

用户视频显示：从 iPhone Chrome 地址栏进入问卷列表后，向下滑动能越过最后一张卡片，继续进入大段空白；等待后页面高度恢复。视频涉及列表首页。

首页改用固定在可见窗口内的页面外壳，由 `main` 单独滚动。文档根与 `body` 不再同时承担列表滚动，列表到达首尾后不向浏览器外层传递继续滑动的手势。列表中间的滚动、反向滑动、水平手势和双指缩放保持可用。页面高度取 CSS 动态视口与 Visual Viewport 测量中的较小值，避免初始旧测量把页面撑长。

视口监听在 `pagehide` 时暂停，在 `pageshow` 时恢复，返回页面和重新切回浏览器时重新测量。零尺寸测量回退到 `innerHeight` / `innerWidth`，不使用定时轮询。评分任务的可见性和布局变化中断规则保持原样，知情同意书和历史冻结版本不修改。

手机号输入框和自定义键盘在同一道题重排时复用原节点，避免窗口高度变化期间丢失焦点和后续连续按键。回归用例在输入第一位后改变窗口高度，确认焦点保留，并继续输入其余十位。

新增回归覆盖 393×664、390×844、320×480 的滚动边界，短列表、触摸边界、陈旧视口测量及多次前进后退恢复。Chromium 随 `npm run test:runner` 执行；WebKit 使用 `npx playwright test --config tests/viewport-browser.config.ts`，首次运行需 `npx playwright install webkit`。桌面 WebKit 的移动视口测试不能替代用户这台 iPhone 的 Chrome 真机复测。

WebKit 仍有与原生视口／键盘底部空白有关的[问题记录](https://bugs.webkit.org/show_bug.cgi?id=292603)。视频没有提供浏览器内部视口数据，不能将该记录直接当作同一根因的证明。
