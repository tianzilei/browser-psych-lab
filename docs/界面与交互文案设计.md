# 界面与交互文案设计

> 并发、准入和容量口径已于 2026-10-11 同步。完整预算、默认 2／1 与特定 ECS 7／7 的区别见 [并发设计与容量验收](并发设计与容量验收.md)。

2026-10-11。本轮沿用原生 DOM、Canvas 和 CSS，保留页首、内容区、底部操作区的布局。参与者首先看到当前说明或题目；项目标题、系统状态和诊断信息降低视觉优先级。没有新增依赖、动画或后台轮询。

## 内容与视觉层级

- 项目标题保留在页首。正文中的同名页面标题隐藏；页面标题与说明完全相同时只显示一次。比较时归一化空白，显示时保留原字符串。说明不因与项目标题相同而消失，也不进行包含匹配、模糊去重或句子删改。
- 没有说明的页面直接显示首题。说明首屏隐藏不可用的“上一段”；有说明时，首题仍可返回阅读。
- 题目进度、必答／可选、多选提示收拢到一行，题干单独显示。无错误时不保留错误空行。
- 主操作用实心按钮，辅助操作用描边按钮。冻结协议决定背景与前景颜色，保持暗色、触控目标和键盘焦点可见。
- 列表仍使用标题与卡片布局，移除品牌眉标和重复的“可参加的问卷”标题，采用与参与页一致的灰色基调。列表失败提供实际重新加载操作。
- 研究者提供的知情同意书、题干、量表标签、任务反馈和结束语保持原内容。默认结束语不再重复保存承诺。

## 系统文案与状态

| 场景 | 主要提示或反馈 | 操作 |
| --- | --- | --- |
| 列表 | 请选择要参加的问卷。 | 进入问卷 |
| 打开问卷 | 正在准备问卷… | 取消并返回 |
| 页面保存 | 正在保存… | 提交后暂时关闭作答控件 |
| 完成并确认 | 研究已完成，数据已保存。 | 返回主页 |
| 网络保存失败 | 暂时无法连接服务器，保存尚未确认。请检查网络后重试。 | 重试保存 |
| 任务或图片准备名额已满 | 当前参加名额已满，请约 30 分钟后重试。 | 返回或稍后重试；不显示等待序位、不自动放行 |
| 作答连接过期 | 作答连接已过期，请重新进入。 | 重新进入 |
| 重复页面 | 请回到原页面继续作答，此页只读。 | 不允许作答 |
| 开始任务准备 | 接下来进行任务，需下载约…… | 准备任务 |
| 图片传输 | 正在下载图片 N% | 取消并返回 |
| 图片与设备检查结束 | 准备就绪。开始后请保持页面可见，并连续完成本组。 | 开始本组 |
| 固定刺激 | 第 N 次呈现 | 研究者设置的响应选项 |
| 响应反馈 | 已选择：…… | 保留选中态 |
| 图片评分 | 第 X/Y 张 | 下一题／提交评分 |
| 本组结束 | 本组已结束，正在保存… | 失败后重试保存 |
| 作答中断 | 本次作答已中断，已有记录已保存。 | 重新作答 |
| 拒绝参加 | 本次不会开始作答。 | 重新阅读知情同意书 |

“已选择”表示界面响应，不表示服务器已接收。只有保存、核对或完成操作成功后才显示保存确认。存储配额、读写失败和未知错误不承诺“答案仍保留”或“已保存”。管理端的答卷状态显示中文，英文状态和完整标识仍可查看；回放和开发检查保留需要的技术证据。

公共文案、错误解释和显示去重位于 `src/web/participant-ui.ts`。`RequestError` 保留响应的 code、HTTP status 和 details；参与页只显示可读解释，原始信息放在默认折叠的“查看错误详情”中。未知代码不会直接作为主要提示。容量、续租过期、其他 409 错误分别处理。

## 交互修复

- 恢复页保留一个恢复按钮，取消两个按钮执行同一动作的情况。只有明确的网络恢复状态响应 `online` 事件，并使用已有单飞锁；活跃输入、组合输入、当前题目和滑块不因联网而重新挂载。容量拒绝仍由用户手动重试。
- “取消并返回”中止准备并返回对应页面；保留准备票据的释放、真实流退出和许可检查。
- 图片评分的题干、进度、所选值分别显示一次。拖动不再高频更新全局状态区；原生 `aria-valuetext` 保留，控件输出关闭重复的实时播报。
- 滑块每张图片开始时明确为“尚未作答”。没有逐级文字标签的问卷量表显示具体分值，替代所有中间值都显示“两端之间”的模糊反馈。
- 单个评分题加年龄题先显示“下一题”，最后才“提交评分”。年龄提示、提交资格和校验均遵循冻结的 `age_min`／`age_max`；非法输入有范围提示和 `aria-invalid`。
- 单坐标轴使用实际可用空间，避免小屏与横屏时覆盖导航按钮。选项和坐标轴还必须在内容区内完整显示；空间不足时提示调整设备，不要求参与者“缩短文字”。

## 运行边界与验证

任务准备后重新测量并冻结几何。运行状态区使用固定高度，任务期间不引入动画，也不因文案长度改变刺激位置。固定刺激、重复调度、评分 ISI、原始事件、资源 SHA-256、保存凭证、封存与冻结协议结构保持既有合同。新版执行器使用新的资源散列；已有冻结执行器继续按原资源工作。

Gemini Bridge 的两轮讨论记录保存在 `docs/gemini全项目设计/ui-*-prompt.md` 与 `ui-*-response.md`。Gemini依据提供的界面结构和实施摘要提出建议；实际行为由本地检查与浏览器回归验证。“拒绝后未记录任何信息”等过度承诺、统一改暗色背景等建议未采用。

完整 `npm run check` 通过：119 项单元测试、42 项问卷浏览器测试、6 项任务浏览器测试，共 167 项；类型检查、构建和 smoke 同时通过。验证结果与源码散列见 `docs/gemini全项目设计/ui-validation.json`。覆盖桌面、手机尺寸、暗色、长文本、组合输入、断网恢复、容量拒绝、知情同意、原生触控、评分与年龄、服务器回放及保存确认。浏览器测试使用 Chromium 与移动设备模拟，不代表已对所有真实设备或浏览器完成测试。

本地预览截图位于 `.local/ui-before/` 和 `.local/ui-after/`，由隔离的 TEST_ONLY 数据库生成；目录不参与发布，也不包含正式研究数据。
