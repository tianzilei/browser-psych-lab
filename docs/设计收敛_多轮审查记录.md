## 2. 已关闭的规范问题

表中“关闭”表示规则已写入最终规范；全部对应测试仍待实施。

| 问题 | 最终规则 | 主规范位置 |
| --- | --- | --- |
| B01：本地提交与短空屏冲突 | 队列/意图在截止点前完成并收到成功通知；分开 L_commit 与 H_activate；失败终止，不延长 ISI | 6.6.3、18.3 |
| B02：最后试次异常无后续位置 | 使用原有空屏内的安全尾部追加；尾部条件必须通过总预算；不插缓冲或填充题 | 6.6.2、18.3–18.4 |
| B03：已锁定补测的迟到纠偏 | QUEUED 可及时持久取消；STAGED 尚未软件出现则终止；已出现后保留固定阶段和记录 | 6.6.3、18.4 |
| B04：在线判定观察点不明 | 图片窗关闭回调记录已处理输入水位/摘要；重放当时证据，不假装已排空未来输入 | 6.3、18.3 |
| B05：动态组超过墙钟租约 | 未关闭 permit 始终独占运行权；第二标签只读；显式未知恢复终止且不重跑 | 9.1–9.3、18.6 |
| B06：单事件 ACK 被当作完成 | 原始接管、语义处置、页/组 seal 分层；精确集合/hash 凭证，seal 前保本地原始副本 | 8.2–8.4、18.5 |
| B07：文件发布崩溃与回收竞态 | 先上传意向，排他发布，登记未知查询原键；完整 refs/pins、DELETING 提交后删除再 PURGED | 10.4、18.8 |
| B08：导出混用快照或无限长事务 | 单 RR 读视图有界物化所有必要内容，释放后打包；超限失败或明确不同 snapshot 包 | 11.3、18.9 |
| B09：路径检查被说成绝对安全 | 可信根/祖先权限、受控对象键与打开身份核对；不宣称单一 realpath/FD 消除全部竞态 | 10.5、18.8 |
| B10：状态箭头允许终止转完成 | 会话终态互斥不可逆；实例执行证据、根结果、系统诊断/人工标记独立 | 7.4、18.1–18.2 |
| B11：暂停误挡已有会话 | 新接入事务签发 admission；暂停前已有凭证者可继续问卷、预留/正式分配、后续组和补传 | 11.6、18.6–18.7 |
| B12：客户端选方案或重复核销 | server 预留→客户端报告准备→正式开始事务分配一次；方案种子私有，补测不再分配 | 4.4、18.7 |
| B13：同 ID 重传吞掉冲突/待核对 | 同 ID/hash 返回原接管凭证与当前处置；异正文另存冲突 receipt；不覆盖原始正文 | 8.3、18.5 |
| B14：原始字节/批次接管含混 | 一次编码 UTF-8、重发精确副本、SHA-256 服务端重算；批次与逐条结果明确，PG commit 后 ACK | 18.5 |
| B15：BEGIN/LSN 被当作逻辑视图 | 记录实际读视图获取点与源集合；LSN 仅审计参照，不代表精确 MVCC 数据集合 | 11.3、18.9 |
| B16：默认 K=2 被误当唯一配置上限 | 非负整数、有限验证 cap；首批覆盖0/1/2，更高先验收；无静默截断 | 4.3、18.4 |
| B17：异常终止伪装感谢完成 | 明确中止与真实同步阶段，后台记录具体原因；不显示正常完成或重做按钮 | 4.5、8.1、18.10 |
| B18：指纹/随机 token 被当作身份保证 | 每 tab 随机 writer_id；凭据只授本会话，无实名不等于绝对匿名；去重不越权 | 9.4、18.1、18.10 |
| B19：发布/灾备被混同原子事务 | FS 与 PG 分阶段；同卷不覆盖发布、明确耐久性；独立目标实副本及恢复演练 | 10.4–10.6、18.8–18.9 |
| B20：开始意图首次在切换点写入 | 已知下一目标提前异步承诺，成功锁定；未决意图临时保护；尾部预算覆盖完整串行/合并路径 | 18.3 |
| B21：取消后再排队与“禁止复活”冲突 | CANCELLED 属提议；固定候选仍可被新合法提议引用，实例从未 STAGED/无未决意图才可用 | 18.2、18.4 |
| B22：只读备份事务写 pin、清单与转储错位 | 生命周期屏障→只读导出快照/清单→独立可写 pin 提交→共享 snapshot 转储→副本核验 | 18.9 |
| B23：随机源不明确或有模偏差 | xoshiro128 starstar 精确32位变体＋拒绝采样，独立种子、稳定候选枚举、draw计数和黄金向量 | 18.4、18.11 |

用户本轮已明确：补测锁定但尚未显示，迟到合法回答使其不必要且无法安全撤销时，终止整个会话并保留数据。设计没有增设“假装完成”“自动换组”或“延长空屏”的替代路径。

## 3. 没有采纳的典型建议

| 返回建议 | 不采纳原因与最终处理 |
| --- | --- |
| 组末才首次保存；为最后补测加额外等待 | 违背既有持久化和固定阶段要求；预算不足即阻断/终止 |
| 内存先取消，之后再补写取消事件 | 可能实际顺序与持久重放不一致；成功提交才生效 |
| STAGED 等于已进入 GPU/VSync 或物理曝光 | 无物理测量证据；仅定义软件锁定/绘制参考 |
| UNKNOWN 开始意图直接计作一次物理呈现 | 占用槽位和已观测 software onset 分开，未知不推断真实曝光 |
| 同 ID 重传一律 ACCEPTED | 必须保留原事件的 pending/quarantine 处置，不能借重试升级 |
| 生命周期终止后补传成功就转正常完成 | 终止不可逆，补传只改善同步/完整性 |
| 每会话独立快照混成一份导出包 | 包内各表必须同一读视图；拆包须注明独立快照 |
| 文件超过一天/租约失效即可删；事务 rollback 可撤回 unlink | 不能证明无引用，物理删除不能由PG回滚；完整账本＋两阶段维护清理 |
| fs.link 接受 O_CREAT/O_EXCL | 返回建议错误；硬链接发布不传这些打开标志，实际环境验收其不覆盖语义 |
| 在 READ ONLY 事务 INSERT BACKUP_PIN | 读写责任冲突；采用独立可写事务并在屏障下配对 |
| “近似无偏”泛称 Lemire/Fast Dice Rolling | 名称与保证混乱；采用简单精确拒绝映射和已命名32位生成器 |
| 软件测试即可证明固定物理 offset | 无法证明；首版只输出软件证据，物理验证后续单独准入 |

## 4. 现在可以启动的实施工作

P0 优先做共享字段与状态字典、不可变原始字节及接收凭证、页/组清单、单写者规则、固定/动态调度纯逻辑和黄金向量。用 TEST_ONLY 条件表、假时钟、注入延迟和崩溃钩子先验证合同。

P1 做单应用＋PostgreSQL＋三个文件存储区、权限/HTTPS、排他发布、维护清理、一致快照/pin 备份和独立恢复。编辑器及正式设备时序验收随后按主规范第13节推进。不需要用户现在追加参数才能建立工程骨架，但测试占位值不能进入正式采集。
