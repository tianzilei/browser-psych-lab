## CVE-2026-111943 的判定与修补

该漏洞涉及 Go 标准库 `crypto/x509.Certificate.Verify` 对已不可信中间证书的处理。官方记录的修补边界为 Go 1.26.10 和 Go 1.27.3；1.27 分支的受影响范围为 `>=1.27.0-0 <1.27.3`，此前分支的边界为 `<1.26.10`。[Go 官方安全发布公告](https://groups.google.com/g/golang-announce/c/66pojueaQek)、[GO-2026-6809 官方记录](https://vuln.go.dev/ID/GO-2026-6809.json)。

应用服务端使用 TypeScript / Node；反向代理 Caddy 的实际构建信息为 Go 1.25.0，处于官方受影响版本范围。Caddy 存在证书管理所需的出站 HTTPS 校验路径；当前反向代理上游为 loopback HTTP。此处确认的是组件版本命中和校验功能的使用，没有执行中间人攻击验证。

远端 Ubuntu 26.04 的已配置软件源在刷新索引后仍只提供 Caddy 2.6.2-14，ca-certificates 已安装／候选版本均为 `20260816ubuntu0.26.04.1`。本次使用官方 Go 1.27.3 工具链，为 Linux amd64 构建 [Caddy v2.11.7](https://github.com/caddyserver/caddy/releases/tag/v2.11.7)：

- Go SDK 取自官方发行地址并核对 SHA-256；Caddy 模块固定为 v2.11.7，保留 Go 校验数据库验证和模块清单。
- 构建使用 `CGO_ENABLED=0`、`-trimpath`，通过 Caddy 提供的 `CustomVersion` 链接参数标明实际源码版本 v2.11.7。二进制 `build-info` 同时记录 Go 1.27.3 与 Caddy v2.11.7。
- 旧 Caddy 没有非标准模块。新版本在 caddy 服务用户下通过现有配置的 `validate`；配置适配前后的域名均为 `tzl.asia`，上游均为 `127.0.0.1:3000`。
- 运行二进制 SHA-256 为 `1e2665659546d37d4ce7894e52f42357224fdc1ea85b179d5ecff4cbb8dc8cf0`。实际 Caddy 进程的可执行文件摘要与其一致，Go 1.27.3 的证书拒绝逻辑已随该运行二进制生效。
