## 当前三份问卷

Gemini 最终给出有条件通过：现有三份 190/191/191 项问卷由必填编号和单轴量表组成，没有 condition。按这些前提，可继续使用现有分段保存与自适应界面。医生独立评分不进入此 renderer，保留原轨迹设置。

该判断不能推广到任意带条件跳转的 adaptive 问卷，也不是“绝对不会丢数据”的保证。

### 条件恢复问题的静态触发链

前段 A=yes 时填写条件题 H=foo，随后将 A 改为 no，H 隐藏。pageSnapshot 将 H 规范为 null，但 append 仍将原始 data 作为本机 page_values 保存。前段已在本机拍快照、尚未由服务器 seal 时刷新，初始化直接合并 page_values 会重新引入 H=foo。后段若依赖 H=foo，客户端可能显示并记录该段；服务器 seal 前段后使用 H=null 跳过该段，双方保存位置和路径就可能不一致。

Gemini 在最后一轮接受了这条推导，建议在初始化恢复时重新做规范化，而不是修改已有原始事件、哈希或 manifest。原始字节仍需保留；规范化应作用于恢复用的答案投影。

讨论阶段的关键待补用例：前段填写后回退隐藏 H → 本机快照 → 阻止 seal → 刷新恢复 → 后段条件应与服务端保持一致 → 恢复上传后正常完成，无路径分歧。后续实施已加入此用例，并覆盖 seal 已确认的恢复；测试结果见执行记录。

## 已撤回或降级的初稿判断

- “upload 无输入死循环/多个定时器风暴”：requested 每轮重置，timer 复用并清除，running 互斥，初稿推导不成立。
- “状态永远停留在等待同步”：seal 后循环继续上传新的服务器当前段，初稿推导不成立。
- “complete 无参 sync 必然越界”：正常入口先要求服务器全部段 seal，初稿忽略了上层约束；可增加防御性收口，但不是已证明的当前缺陷。
- “键盘视口变量未更新”：viewport.ts 已监听 visualViewport 并更新根 CSS 变量，重复在 layout 里赋值不必要；真实手机键盘行为仍属于需覆盖的适配测试。
- “快速上一页导致索引越界”：busy 和 undefined 分支已防护。
- “每段最多 31 个事件”：该说法错误；revision 按每次有效修改累计，题数不能单独证明不超预算。
