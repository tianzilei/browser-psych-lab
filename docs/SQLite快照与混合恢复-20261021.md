## 决策与边界

- **不做文件级加密**。离线副本只放在开启 FileVault/BitLocker 的个人电脑或加密移动硬盘；不使用公共网盘、微信文件传输或未加密 U 盘。
- 当前库并非匿名数据：医生评分版本含 `compensation-phone`（`input_purpose: personal`，11 位手机号），`lab_covariates` 含 60 条 `server-observed`（IP、User-Agent 等），交互记录默认开启。服务端本机 `700/600` 权限和离线设备的全盘加密是当前的静态保护。
- 如果离线副本将来进入公共云盘或未加密介质，必须先加系统级加密或口令压缩包。

## SQLite 快照

脚本：`/usr/local/bin/psychlab-sqlite-snapshot.mjs`（源码 [`scripts/sqlite-snapshot.mjs`](../scripts/sqlite-snapshot.mjs)）

流程：

1. 计算业务数据指纹；与 `.last-sqlite-fingerprint.json` 相同则跳过（零写入）。
2. 校验基准指针与当前 assets/runners 兼容；不兼容时先运行全量 Wrapper 生成新基准，并把新目录标记 `.keep`、更新指针。
3. 使用 `better-sqlite3` 的 SQLite Online Backup 写入 `/dev/shm`（不足 256 MB 时回退 `STORAGE_ROOT/tmp`）。
4. 验证 `integrity_check`、`foreign_key_check`、`verifyEvidence`，并确认快照结构被基准覆盖。
5. `zstd -19` 输出到 `research-backups/sqlite-snapshots/`，写 `.json` 元数据与 `.sha256`。
6. 保留最近 **5** 份 SQLite 快照。
7. 在备份开始前保存数据指纹；备份期间的新写入会触发下一次，不会被误标为已备份。

## 混合恢复

脚本：`/usr/local/bin/psychlab-restore-hybrid.mjs`（源码 [`scripts/restore-hybrid.mjs`](../scripts/restore-hybrid.mjs)）

```bash
node /usr/local/bin/psychlab-restore-hybrid.mjs \
  /var/lib/browser-psych-lab/research-backups/df3a856e-15ad-46a6-8641-1573ae6baf71 \
  /var/lib/browser-psych-lab/research-backups/sqlite-snapshots/sqlite-20261021-012055.sqlite.zst \
  /独立目录/restore-target
```

步骤：

1. 用现有 `restoreBackup` 恢复基准 bundle，得到图片、runner 和初始数据库。
2. 校验快照 SHA-256、基准 manifest 哈希和 assets/runners 覆盖关系。
3. 解压快照覆盖 `database/browser-psych-lab.sqlite`，删除 `-wal/-shm`，权限 `600`。
4. 执行与 `restore.ts` 一致的安全复位：
   - `collection_gate='CLOSED'`
   - 删除 `lab_admin_tokens`
   - `RUNNING` 作业标为 `RECOVERY_REQUIRED`
   - 删除 `p0_meta.app_instance`
5. 运行完整性、外键、证据校验，写 `hybrid-restore-report.json`。

本次演练结果：11 个研究、63 个会话、60 个资产、191 个封存、13,589 条证据全部通过；旧版研究为 0；gate 关闭；admin token 为 0。报告保存在：

`/var/lib/browser-psych-lab/backup-verification-df3a-20261021/hybrid-restore-report.json`

临时恢复目录已删除。
