# 问卷前端轻量化与纯色设计

2026-10-08–09，按用户要求与 Gemini bridge 完成三轮设计、代码和交互讨论。参加者问卷改用原生按钮、李克特坐标轴和逐题导航，移除正式路径的 SurveyJS；开发检查页仍可显式加载 SurveyJS 样例。[讨论原文和取舍](gemini前端讨论/README.md)保存在项目内。

## 固定视口与纯色页面

参加者页面使用灰色 `#e5e5e5` 或深色 `#202020`、系统字体、纯文本、简单边框和可见的键盘焦点，无外部字体、背景图、渐变、阴影、动画、Markdown 或富文本解析。编辑器的“参加者页面 → 纯色背景”提供两种预设；背景沿用 `layout.background` 随版本冻结，加载后一次计算亮度以选择黑/白前景和原生控件配色。既有自定义背景不被自动改写。

`participant.css` 固定根页面并禁止双向滚动、滚动链和非输入区域的拖曳。主区域绑定 `visualViewport` 的宽、高及偏移，兼容浏览器地址栏和软键盘挤压；不支持该 API 时使用窗口尺寸。尺寸事件只合并到下一帧处理，没有轮询或持续动画循环。

页眉与内容采用 14%/86% 分区；题目区将题干、答案和底部导航按比例分配，保留按钮最小触摸尺寸。问卷主体最大宽 900px，导航分配 34%/64% 和 2% 间距。手机横屏和窄屏通过分页减少同屏内容，不增加内部滚动容器。标题栏可省略，但研究标题全文在说明阅读流程中保留。

## 按钮与阅读流程

同屏显示一题。单选和多选使用原生 `button`，以 `aria-pressed` 表达选择；Tab、Space、方向键、Home/End 可操作并有焦点样式。答案点击立即响应，不触发输入法，也不自动跳题；“下一题”和“上一题”承担明确导航。李克特量表使用下述离散坐标轴。

2026-10-09 按用户反馈取消所有选项分页及长选项独立阅读视图。每道单选、多选题的全部选项都在同一屏的网格中显示，文字完整换行；按宽高寻找能容纳所有控件的列数，按钮保留最小 44px 触摸高度。不能完整显示时不裁切、不缩小文字，阻止继续并提示调整设备或减少/缩短选项；恢复可用尺寸后保留先前答案。

主按钮只显示“阅读下一段 → 下一题 / 提交本页”。导航使用 200ms 的短锁避免连点跳过两个状态，选项点击不受该锁影响。提交前同步锁定，防止重复快照。

`text-pager.ts` 根据当前文本区域的宽高测量可容纳内容：隐藏测量节点限定尺寸，二分查找边界；`Intl.Segmenter` 按字素切分，兼容回退按码点切分。只测量当前段，缓存最多 64 种段位置/尺寸组合；输入时不测量文本。说明和题干完整保留，不解析标记。选项不使用该分页器、不省略文字，保存值始终是原始完整选项。

空间连一个字素都无法完整显示时，阻止继续并提示收起键盘或调整设备，避免把裁切文本当作已阅读内容。支持 Intl.Segmenter 时，分段保护 emoji 和组合字符；兼容回退仅保证码点完整。分段不保证恰好在句末结束。

## 李克特坐标轴

量表保留整数 `min` / `max`，新增研究者预设的 `min_label` / `max_label`（各最多 40 个字符，建议 12 字以内）。管理端仅上传 JSON，简化格式用 labels 首尾配置两端，量表不使用 `choices`；共享合同拒绝给量表附带选项。发布前必须填写两个非空端点文字，否则返回 `SCALE_ENDPOINTS_REQUIRED` 并显示中文提示。旧冻结量表解析保持原样，缺少文字的版本须由研究者配置端点后重新发布，不自动推断端点含义。

`scale-input.ts` 创建一个原生 range 控件、两端文字、整数刻度和预设文本反馈。点击或拖动轴线按最近整数刻度选择；方向键、Home/End、Space/Enter 也能操作，不唤起输入法。初次显示没有已选点、不写入默认中间分；只有明确操作后才写 PAGE_REVISION。零和负分仍为合法数值，拖动后的重复同值事件去重；可选量表提供“清除”并保存 null。刷新和返回题目恢复真实已选值。

布局测量只发生在导航或尺寸变化时；滑动值变化不重建轴或测量选项布局。两端文字、轴线和按钮无法完整容纳时也阻止继续。

## 个人信息与输入法

用户已明确选择：**仅个人信息允许文字输入，其他文字题禁止发布。**

文本题新增显式 `input_purpose: "personal"`。编辑器将该题型称为“个人信息输入”，提供“此题仅用于个人信息”勾选项。保存草稿仍允许研究者修改旧文字题；发布接口逐题检查，未标记的文字题返回 `PERSONAL_INPUT_ONLY`，编辑器显示中文修改提示。给非文本题标记用途或使用其他用途值会被共享协议校验拒绝。

历史协议解析保持原有内容和哈希语义，不推断、补写个人信息用途。当前参加者问卷检测到未标记的历史文字题时，不创建输入控件并提示联系研究者更新版本；历史答案和事件不被清除。研究者应把普通文字题改成按钮选项，只有确实用于个人信息的题才标记后重新发布。

个人信息使用原生 text input，不自动聚焦。聚焦后折叠页眉和题干，让有限可见空间容纳输入框及底部按钮；“完成输入”先收起键盘，下一次导航才继续题目。输入失焦时不立即移动导航按钮，避免它在 pointerdown 与 click 之间变位。合成输入期间保留输入修订、焦点和控件值，合成结束后更新分支；合成未完成时禁止导航或提交。

## 分支与可靠保存

答案改变时按协议顺序计算可见题；隐藏题保留本机草稿，但对下游条件求值视作 null，前进和后退都跳过隐藏题。重新显示时恢复答案；最终服务端按 SKIPPED 处理隐藏值。量表保存 number，包含零和负数；多选按协议选项顺序保存数组，允许可选题取消全部选择。

每次实际值变化立即写 PAGE_REVISION，复制答案和数组快照后交给现有 IndexedDB 串行事务队列，不防抖。input/change/compositionend 的同值事件去重。最后一步只验证可见必答题，未完成时返回该题；合法提交写一次 PAGE_SNAPSHOT 并继续原有上传、封存、离线恢复流程。当前题 ID 另存 sessionStorage 以恢复导航位置。更换页面、保存失败或名额失效时清理测量观察器、帧回调及导航计时器。

图片页面额外加载 `runner.css`：Canvas 按剩余槽位和冻结宽高比适配，响应按钮采用网格，“开始本组”占固定底部槽位。开始后仅隐藏按钮，避免移除元素导致几何变化；Canvas 空屏仍填充冻结背景。运行期间窗口、可见视口或方向变化会中断任务并保存记录，不在组内重新缩放。达不到协议最小 Canvas 宽度的设备在开始前拒绝运行。历史图片运行器仍使用其归档版本。

## 文本预算

共享 `TEXT_LIMITS` 保持原协议预算，编辑器 maxlength 与服务器校验同源；短屏通过按段阅读控制每屏文字量。

| 字段 | 硬上限 | 编辑建议 |
| --- | --- | --- |
| 研究、页、组标题 | 200 个字符 | 120 字以内 |
| 题干 | 1000 个字符 | 300 字以内 |
| 每页说明 | 8000 个字符 | 保留必要说明/知情同意全文 |
| 每个选项 | 200 个字符 | 建议 20 字以内，全部选项须同时适配设备 |
| 坐标轴端点文字 | 每端 40 个字符 | 建议 12 字以内，发布前必填 |
| 个人信息答案 | 题目指定的 1–4000 个字符 | 新题默认 200 |

硬预算按现有 JavaScript 字符串长度（UTF-16 单元）计算。每研究最多 30 页、每页 30 题；选项题 2–20 项、量表最多 21 个整数刻度、图片响应按钮 2–6 项。软提示未缩小历史合同的硬上限。
