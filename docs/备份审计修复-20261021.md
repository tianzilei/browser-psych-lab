# 备份与导出清理审计修复

2026-10-21。本页记录仓库代码的修复与本机验证；不代表服务器已更新。

## 行为变化

- 全量 Wrapper、SQLite 快照和 monitor 共用 `scripts/lib/backup-integrity.mjs`。业务指纹在同一 SQLite 只读视图中按主键扫描业务内容，包含研究排序、每个研究的开放状态和环境验收记录；原始正文用其不可变 SHA-256 表示。备份作业、审计、幂等请求、pin 和派生索引不参与摘要，避免备份自身触发下一次备份。
- 指纹格式升级为 `business-content-v2:<SHA-256>`。已有 sidecar 不需要手动修改；下一次全量/快照会因格式不同执行一次备份，之后继续按变化跳过。指纹仍在备份开始前计算，期间的新业务写入会触发下一次备份。
- 冷归档启用 `pipefail`，先写临时压缩文件，再解包核验 manifest 身份及其中每个文件的 SHA-256，成功后同步并原子替换正式归档，最后登记作业并删除原目录。验证优先使用空间足够的 `/dev/shm`，否则使用系统临时目录。失败时保留原包并清理本次临时文件；READY 作业遗留的旧归档会重新生成，ARCHIVED 作业的残留源目录也须在归档校验通过后才删除。
- 选择/复用基准和检查备份健康时，核验清单中的实际文件及指针记录的 manifest 哈希，并检查资产和运行器引用。基准文件缺失或内容不符时，快照请求刷新基准，monitor 报 `ALERT`；快照的元数据哈希也须与压缩文件一致。
- 导出快照清理把重命名纳入回滚范围。重命名或数据库事务失败时恢复已移动目录；回滚失败会明确报错。再次用同一研究和 `--apply` 运行时，自动恢复 READY/FAILED 作业遗留的 `.purging-*` 目录，或继续删除已登记 PURGED 的残留目录。已有非空规范目录时拒绝覆盖；dry-run 发现残留会报 `EXPORT_PURGE_RECOVERY_REQUIRED`，保持文件不变。

## 安装依赖

三个备份入口继续默认从 `/opt/browser-psych-lab/current` 加载依赖。发布该版本时，发行目录须同时包含 `scripts/lib/backup-integrity.mjs` 和 `scripts/lib/backup-archive.mjs`，并更新 `/usr/local/bin/psychlab-light-backup.mjs`、`psychlab-sqlite-snapshot.mjs`、`psychlab-backup-monitor.mjs`。仅替换旧的独立入口文件不足以升级。

`BACKUP_RELEASE_ROOT` 可指定其他绝对发行路径，用于本机测试或非默认安装；默认路径不变。导出清理从仓库执行，依赖相邻的 `scripts/lib/export-purge.mjs`。归档主机需要 Bash、tar 和 zstd。
