# 设备保存预算与准备阶段记录

2026-10-16。新增准备诊断记录和设备 CSV，并修复点击准备后没有明确进度反馈的问题。

## 页面准备

旧冻结运行器的初始 `#status` 为空，程序资源加载、恢复会话和接口重试期间缺少反馈。线上旧程序和 CSS 的压缩传输合计约 40 KB；本次访问均正常返回。没有复现受试者那一次完整的一分钟等待，尚不能把全部延迟归因于网络、设备或服务器中的某一项。

点击“准备任务”后，主页面现在立即显示程序加载进度、等待秒数和取消按钮；先将该冻结运行器实际引用的程序和样式资源载入浏览器缓存，再进入任务页。最多 3 个资源同时加载，总限时 45 秒；10 秒后提示网络较慢。取消回到准备入口，超时和资源失败显示可重试的错误。

新运行器初始化时立即显示“正在恢复作答并连接服务器”，随后分别提示方案确认、下载许可、图片下载、刷新检查和保存速度检查。错误先显示，再清理续租，避免清理请求延长无反馈等待。旧冻结运行器文件不变；通过更新后的参与主页进入旧任务，也会先显示程序加载页。

## 记录与保存

新记录使用 `preparation-v1`，追加到既有不可覆盖的 `lab_covariates`，来源为 `preparation-reported`。设备信息为浏览器自报，配置预算按会话冻结问卷验证，问卷版本、协议和运行器摘要从服务端关联。

- 程序加载：开始时间、总耗时、HTML 与资源加载耗时、READY／FAILED／CANCELED。
- 设备检查：组 ID、恢复会话、准入、方案确认、下载、刷新和存储检查耗时。
- 保存性能：配置的 `commit_ms`、实测最大耗时、全部 10 次样本、测量路径、审计负载字节数和屏幕帧间隔。
- 设备：user agent、平台、语言、处理器数量、可用时的内存档位、视口、DPR 和浏览器网络信息。
- 准入结果：READY、FAILED 或 STORAGE_REJECTED；超预算后也保存测量结果。

每次准备使用独立 attempt_id，原始 JSON 先严格保存在 IndexedDB，收到匹配摘要回执后才标记已同步。网络失败保留原字节重试，不改变事件链或实验答案。每个会话最多 100 条准备记录，与原环境采集额度分开。准备诊断在任务开始前或结束同步时上传；任务循环不等待诊断网络回执。

达到 100 条后停止新增准备报告，已保存的报告继续补传，不替换既有原文；该容量边界不阻断设备检查、任务导航、答案保存或终止对账。真实 IndexedDB 保存失败仍走保存错误处理，不作为容量到限忽略。

## 导出与分析

管理页执行“导出问卷结果”或“下载数据”后，链接区新增“下载设备与准备记录 CSV”。文件使用带问卷名、设备记录后缀和北京时间的下载名。两种导出都包含 `preparations.csv`，轻量答案导出继续不扫描轨迹正文。

CSV 的 `preparations_layout` 为 `device-preparation-v1`。主要字段包括 session_id、version_id、protocol_hash、runner_hash、group_id、configured_commit_ms、measured_commit_ms、storage_result、samples_json、probe_path、elapsed_ms、stages_json 和设备字段。耗时统一为毫秒，received_at 为服务端 Unix 毫秒时间。commit_ms 为每轮四次保存路径的总耗时，取 10 轮中的最大值；storage 阶段耗时包含全部 10 轮，不应直接与单轮预算比较。

`record_source` 区分三类行：

| 来源 | 含义 |
| --- | --- |
| client-preparation | 一次客户端准备阶段的原始测量报告，通过 attempt_id 区分重试 |
| permit-readiness | 运行许可中已保存的准备测量，可读取历史实测值 |
| configuration-only | 没有准备报告或运行许可，只能关联该会话的冻结配置 |

同一次准备可能同时有客户端报告和许可记录，分析时按来源筛选，不能直接把 CSV 行数当成设备数。`storage_result` 为 PASSED、REJECTED 或 NOT_MEASURED；程序资源 READY 不表示存储性能通过。历史缺少的失败样本留空，标记 NOT_MEASURED，不补造测量值。没有任务组的纯问卷使用 NOT_APPLICABLE。

## 验证与发布

本机类型检查、154 项单元测试、6 项生产构建浏览器回归及 3 项运行器回归通过。覆盖冷资源延迟下的可见进度、取消准备、慢会话恢复计时、超预算设备的 10 次样本保存、不同冻结预算的比较、摘要冲突、不可变记录、CSV 下载和旧数据缺项。

服务器隔离副本使用相同协议、新运行器及每次摘要增加 25 毫秒的模拟延迟，完成 32 张和 224 个值的保存。553 条原始记录摘要、哈希链和精确封存清单核对通过，最短图片间隔 3014.8 毫秒。程序加载和设备检查两条报告保存成功，实测单轮最大 116.6 毫秒，配置预算 1000 毫秒。新增 CSV 共 3 行、3797 字节，实际 HTTP 下载摘要一致。

上传出现 3 次临时 503，原客户端重试后正常完成。完整浏览器脚本在全量 data.csv 的下载阶段达到请求工具的 30 秒限时，原失败报告保留；随后独立验证完成状态、原始数据及新设备 CSV。未将这次大文件下载限时写成评分保存失败。

历史核查基于发布前生产数据库快照，以只读 worker 为 5 份开放问卷生成轻量答案与设备 CSV，快照摘要保持原值。医生评分的 17 个历史会话中，12 个有保存耗时，5 个缺测；其他 4 份纯问卷共 36 个会话没有存储准入实测，保留缺测／不适用状态。
