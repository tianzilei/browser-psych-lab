MPA 内存与页边界：多入口（MPA）切分的是构建时的代码依赖图与 HTML 文档入口，能确保时序运行页（/participant/runner）的入口 Chunk 零引用 SurveyJS。但浏览器进程可能在多页面间复用 Renderer 进程、延迟垃圾回收（GC）或激活 BFCache。“切页面即完全销毁 V8 Heap 并彻底回收内存”是不成立的推断；时序页的真实内存驻留与事件循环底噪必须在真实目标机型（尤其是微信 WebView）上实测。跨页迁移必须依赖服务端已确认的锁页凭证与进度状态，仅凭前端 localSaved 无法放行；进入时序页必须建立独立的 clock_epoch，组执行许可（Group Permit）在环境与资源门控完全就绪后由服务端核发；绝不允许将可用的会话 Token 直接拼在 URL Query 中暴露。

事件、摘要与状态层级：原始事件的规范化字节必须包含会话身份、Schema 版本、上下文/Trial 序号及载荷正文；event_id 是独立单调标识符，相同载荷出现在不同 Trial 位置不可直接断言为相同 Hash。重试命中“同 ID 异 Hash”必须写入隔离审计表（quarantine）；系统的状态遵循原定的 custody（保管权）、disposition（处置判定）与 seal（封印核对）分层状态机，正常完成与异常终止各自走对应的核对与封存流水线，不存在一个全局粗暴的 SEALED 状态去覆盖原分层。

已观测事实与未来意图的落盘边界：SOFTWARE_ONSET、输入坐标与按键释放是已发生的物理/软件观测事实，不可能在事实发生前预先落盘。系统只对未来的队列变更、取消操作以及“开始执行意图（Start Intent）”设置不可跨越的本地事务落盘截止点；已观测事实在内存聚合后增量写入本地存储。不能为了“所有事实必须 commit 才能进下一阶段”而人为拉长固定的刺激呈现时间或刺激间隔（ISI）。

准备阶段阻断 vs 计时阶段不可逆：组前准备期的图片下载、格式校验与解码失败属于可恢复故障，此时应阻断进入并允许受控重试或退出；只有进入时序任务后，切后台、严重掉帧或写失败才触发不可逆会话终止（TERMINATED）。软件 onset 使用当前绘制帧的 Draw-call 完成时间戳作为参考基准，不推迟到后续事件循环再次猜测，且严禁过度解释为屏幕物理光子曝光。

素材校验与编解码选型：仅靠文件头 Magic Bytes、Chunk 标记与尺寸头无法保证压缩数据在客户端解码时不崩溃。自研纯代码轻量头解析不可作为完整解码安全凭证，亦不可为了零依赖自研全套图像 Codec。首版推荐：在上传暂存区执行有界的文件格式、静态性与尺寸头扫描；完整解码验证委托给成熟图像库在受限的独立 Maintenance Worker 中异步完成并持久化校验通过标记，正式图片分发时直接透传原图，绝不在服务链路中动态转码。具体解码库在 P3 阶段锁定。

HTTP 缓存与共享设备：浏览器的 HTTP 传输缓存完全由网络栈控制，不受前端 CacheStorage（Cache API）管辖，调用 Cache API 无法清理 HTTP 磁盘缓存。不能采用 private, max-age 并宣称在被试结束后能可靠清理共享设备缓存。首版私有刺激素材统一采用 Cache-Control: private, no-store, no-transform，由服务端同源流式授权返回；组前在客户端内存中完成复用与 Hash 去重，组内零网络拉取。只有带构建 Hash 的公共静态 JS/CSS 才能配置 immutable。

分支状态与安全性表述：问卷 UI 配置的 clearInvisibleValues 选项绝不可直接物理抹掉数据库已接收的原始记录，亦不可将未触发的分支状态直接推断为“跳过”。分支限制为受限 AST 属于控制业务复杂度与确定性，未经验证不能断言 SurveyJS 内置表达式必然导致任意 JavaScript 代码注入。SHA-256 是哈希摘要，不是加密签名；研究者鉴权基于标准的单机凭证与安全 Cookie 即可，无需引入非对称 PKI 架构。

Worker 与 I/O 争用现实：专职 DB Worker、只读连接、图像解码与 Gzip 压缩均会抢占宿主机的 CPU 核心与物理磁盘 I/O，不存在所谓的“零阻塞”与“零争用”。关键权限与会话状态检查必须放在数据库写事务内部执行；PRAGMA wal_checkpoint(PASSIVE) 同样会产生磁盘 I/O 与短锁竞争；系统重启时不清理未决的 Pin 与 Permit，未知状态转化为最终失败前严禁直接复活会话。

工程现状基准：当前工程仅通过了 SQLite BLOB 存储、唯一约束、事务基础回滚、只读视图及 Online Backup 重开连接的夹具测试；未经过真实多线程锁等待、专职 Worker IPC 压测与 20 人集中负载验收。禁止把设计方案描述为已验证事实。

C. 核心可靠性复杂度 vs 可推迟特性
必须保留的系统复杂度（绝对不能删减）

研究管理与不可变版本冻结：卡片编辑、条件表与研究配置必须在发布时生成唯一的 SHA-256 摘要与只读快照。

完整数据凭证与质量标记：数据管道必须完整保留原始 UTF-8 字节、独立单调 event_id、内容哈希、以及时序抖动和切后台告警，保证科研审计链条完整。

分层状态机与状态栅栏：custody、disposition、seal 的状态划分，以及 writer_epoch / permit 乐观锁机制必须完整实现，防止并发脏写或数据被静默覆盖。

有界物化 CSV 导出：基于快照副本的有界分块导出机制不可精简为内存拼装全表字符串，防止大并发下 V8 进程 OOM 崩溃。

可以推迟实现的功能（P3 / P4 考虑）

服务器端全自动图像转码与优化：推迟实现，首版强制研究者在上传前自备合规尺寸图片，服务端仅做校验与拦截。

跨请求的有界组提交（Group Commit）：首版维持单请求独立短事务，只有在真实物理磁盘压测不达标时才引入。

研究者端实时动态仪表盘与 WebSocket 遥测：管理端仅提供基于 HTTP 的离线刷新与轮询，不引入长连接架构。

多用户协作与细粒度 RBAC 权限系统：维持单研究者模型，不引入复杂的用户与组织架构表。

基于专用 Worker 的客户端本地存储：维持主线程 IDB 异步调用，不提前设计复杂的客户端多线程存储管线。

从 SurveyJS 切换到自研原生 DOM 有限渲染器：

触发条件：在目标测试手机（特别是低端 Android 微信 WebView）中，问卷页面初始化耗时超过 500ms、页面切换卡顿超过 100ms，或标签页总内存占用持续超过 120MB 触发系统内存告警时。

在 DB Worker 中开启有界组提交（Group Commit）：

触发条件：在 20 并发采集模拟压测中，若宿主机磁盘的单次物理 fsync 延迟持续高于 15ms，导致主线程请求队列积压经常触碰 N=30 上限并频繁向客户端抛出 503 时。

从 better-sqlite3 迁移到 node:sqlite：

触发条件：Node.js 官方正式将 node:sqlite 标记为稳定（Stable），并且底层原生提供了类似 sqlite3_backup_* 的无阻塞在线热备份与锁状态绑定能力，同时通过现有的全部 BLOB 与并发回归测试。

开工阻塞问题与后续测量准入
必须在写业务代码前解决的开工阻塞问题（Blockers）

多入口打包隔离验证：在构建配置中彻底阻断公共工具层向 /participant/runner 泄漏 SurveyJS 依赖。必须在 CI 构建断言中检查 runner 入口产物的引用包列表，确保其完全纯净。

专职 Worker 的进程级死亡确认机制：必须编写底层测试，验证当调用 worker.terminate() 时，若底层陷入系统调用，主线程能否通过可靠事件（如线程 exit 事件）确认其物理销毁，确保在生成新的 Worker 连接前绝不会产生 Dual-Writer 锁冲突。

规范化序列化一致性测试套件：确立前后端完全通用的规范化 JSON 键排序与 UTF-8 编码实现，确保同一数据结构在不同操作系统、不同 JavaScript 运行时（Node 与移动端浏览器）下生成的 SHA-256 摘要严格一致。

正式采集前的后续测量准入标准（Admission Criteria）

磁盘物理性能基准测试：在部署主机的目标文件系统上运行单线程串行 fsync 探针测试，获取 1000 次提交的耗时分布。若物理 P99>20 ms，必须在系统设计中正式评估并开启有界组提交。

20 人并发网络突发基准：在目标网络环境下，使用 20 个并发实例同时发起 50 张私有图片（总计约 300–500MB）的有界下载拉取，检验宿主机网卡带宽是否被打满，确认 Fastify 主线程的 Event Loop Lag 在此期间未超过 30 ms。

微信 WebView 行为基准测试：在至少两台主流 iOS 与 Android 目标真机（包含微信内置浏览器环境）上，完整跑通准备阶段、时序阶段与终止流程，验证 touch-action: none 的防滚动效果、横竖屏旋转响应以及切后台事件捕获的 100% 可靠性。

声明：本讨论仅完成系统架构方案与协议边界的闭环收敛，并未证明系统已具备实际的 20 人并发采集能力；所有容量与稳定性承诺必须在通过上述测量准入后方可成立。
