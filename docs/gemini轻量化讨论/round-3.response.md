纠正与对齐第 2 轮残留冲突

在展开前端时序与资源传输前，先彻底修正并固化上一轮遗留的 7 处原则性冲突：

第二标签页（Second Tab）语义精化：

普通第二标签页打开时，仅以只读状态呈现，绝不自动终止旧会话。

只有用户在明确提示下主动点击“未知恢复”确认时，才吊销执行许可并终结旧会话（状态置为 TERMINATED），且本会话实例永不再开启新执行。

终结仅代表关闭前向推进与执行权；在离线 Outbox 中积压的合法旧原始字节流，仍可在后续授权接管流程中上传并用于历史完整性核对，绝非“停止一切写入”。

队列 FIFO 与控制优先级的并存逻辑：

主线程排队内，“终止会话（TERMINATE）”指令作为控制帧，可调整至会话队列头部投递，但绝不能跳过或中断当前正在 Worker 中执行 COMMIT 物理系统调用的在途 RPC。

被控制指令插队的原有时序数据帧绝不丢弃，保留在队列或本地 Outbox 中，后续按历史凭证链核对。

主线程内存排队与 UNKNOWN 的边界区分：

从未发送至 Worker 的积压请求，遇崩溃或主动熔断时，状态是确定性的“未接管（NOT_INGESTED）”，客户端可安全重试或等待。

只有已经通过 IPC 发送至 Worker、处于处理中、或 Worker 崩溃导致未收到 Commit 回执的在途请求，状态才被定义为 UNKNOWN。

Worker 崩溃与原生锁安全：

Worker RPC 超时不能推断线程已物理终止。调用 worker.terminate() 无法保证底层正在陷入 C++ 同步系统调用（如 fcntl/fsync）的代码瞬间安全退场。

在收到 OS 级 Worker 线程 exit 事件之前，绝对禁止派生第二个 DB-Writer 实例。若无法确认退出，系统必须保持 503 拒绝服务；若 Node 发生整体 OOM，依赖外部进程守护（如 systemd）整体重启。

重启恢复与 Checkpoint 证据链：

数据库重启自检绝不按“时间戳超时”猜测并重置挂起的许可（Permit）、上传、Pin、删除状态，必须依据事务日志与数据库已记录的事实凭据执行状态机恢复。

优雅停机或启动时的 Checkpoint 不默认执行 TRUNCATE（避免阻塞在长读锁上导致停机挂起），退化为有界等待的 PASSIVE 或 RESTART。

冲突记录与事务状态：

客户端重发命中“同 ID 异 Hash”等逻辑冲突时，不能单纯将数据库事务回滚（Rollback）了事。

必须通过一个成功提交的事务将该异常载荷记录至冲突审计表（quarantined_events），赋予明确的持久化冲突证据，再向客户端返回业务拒绝响应。

驱动与网络选型的保守边界：

node:sqlite 暂缓采纳的唯一依据是：better-sqlite3 已在当前测试工程中通过了锁等待、db.backup()、原生 BLOB 及只读并发的回归测试用例，而 node:sqlite 尚待能力对齐与长周期验证。不做未核实的实验等级与功能缺陷断言。

默认采用本机 Loopback TCP，仅因其无需管理文件系统 Socket 权限与僵尸句柄，足以满足本地反代需求；研究者权限校验必须在专职鉴权层完成完整签名与数据库持久化凭证查验，不依赖主线程元数据预检。

推荐方案：基于文档隔离的 MPA（多入口独立页面）。

/participant/survey：承载问卷引擎，加载 SurveyJS。

/participant/runner：承载 Canvas、帧调度器、PRNG 动态补测。

跨阶段流转：问卷完成并确认本地落盘后，通过 window.location.replace('/participant/runner?session=...') 彻底销毁前序文档的 DOM 树与 V8 JavaScript Heap。

失败边界：

文档跳转重置了浏览器的 performance.timeOrigin，旧页面的绝对时间戳与新页面不可直接相减。进入 runner 必须初始化独立的 clock_epoch，与服务端核对握手时间。

组内严禁任何导航、刷新或回退；一旦在时序执行中触发页面离开（beforeunload / pagehide），直接判定会话损毁（TERMINATED），只允许补传已落盘数据，不可重跑。

组执行许可（Group Permit）仅在 /participant/runner 页面就绪、预加载解码完成、环境检测通过后，由服务端原子核发。

验证场景：在低端移动设备上，检查从问卷页跳转到 Canvas 页后，浏览器内存占用（通过 Chrome Remote DevTools 观测 JS Heap）是否完全回落至纯净状态。

落实阶段：马上可落实。Vite 配置 build.rollupOptions.input 拆分两个 HTML 入口文件。

2. 首版 SurveyJS 受限运行 vs 自研 DOM 渲染器

功能矩阵与实现归属：

功能特性	SurveyJS 内置能力	自研 DOM 渲染器必须实现的成本	本项目首版工程规约

量表与多选类型	强类型数据绑定（Array/String/Number）	需编写表单提取器、反选逻辑、全选排他项校验	沿用 SurveyJS 数据模型。

分支引擎安全性	内置高风险通用求值器（可执行注入代码）	编写受限 AST 解释器（天然安全）	必须由本项目强制约束：禁止通用表达式，采用 JSON Schema 白名单校验。

推荐方案：首版保留 SurveyJS，实施严格沙箱与协议约束。

禁止在问卷中使用任何自定义 HTML 注入题型；

限制分支逻辑为有限 AST 结构：深度 ≤3，仅允许二元比较符（==, !=, >, <, >=, <=, in）和逻辑符（and, or），禁止调用原生函数或动态代码；

配置 clearInvisibleValues = "onHidden"，避免分支隐藏题残留脏数据污染导出快照。

失败边界：问卷配置 JSON 提交时，服务端进行 AST 节点数与操作符白名单校验；超过复杂度上限（如节点数 >10）直接拒绝发布。

验证场景：构造带有恶意脚本（<script>, onerror=）及深层递归嵌套表达式的问卷 JSON，验证发布端拦截机制与前端渲染器的白名单解析。

落实阶段：P0 级落实（编写前后端共享的 Survey Schema 校验器）。

推荐方案：

每一次绘制分别采集两个时间戳：rAF(callbackTimestamp)（合成器上一帧理论时间）与绘制方法调用后的 performance.now()（主线程 Draw-call 完成时间）。

严格声明 software_onset_time 为软件排障数据，不作为物理像素曝光凭据；

抛弃 requestVideoFrameCallback（仅用于 HTMLVideoElement，不适用于 Canvas）；

PerformanceObserver（LongTask）仅作为诊断辅助。如果宿主环境（如 iOS 微信 WebView）不支持，降级记录 longtask_unsupported = true，不中断实验。

时序队列必须保持：固定前缀序列 + 基于 xoshiro128 1.1 的确定性后缀。绝不允许为了对齐帧率而动态插入空白缓冲帧或擅自调整刺激间隔（ISI）。

失败边界：

若在刺激呈现期间检测到单帧耗时异常（例如帧间隔跳跃超过设定的安全容差），记录异常诊断帧；

若触发页面切后台（visibilitychange 变为 hidden）或视口缩放失焦，触发不可恢复的会话终结流程。

验证场景：在 60Hz、90Hz、120Hz 刷新率的真机上运行固定 200ms 的图片呈现，校验记录的绘制时间戳序列分布与单调递增性。

落实阶段：需要真机测试。

4. 遥测日志编码、精确 Float64 与分级持久化

推荐方案：

高精度数据保真：帧时间戳与输入坐标采用原生的 Float64 保留在连续结构化数组中，禁止在客户端将毫秒数四舍五入为整数微秒，禁止使用平均值替代原始轨迹。

规范化序列化与摘要生成：

采用确定性字段排序的序列化器；

使用 new TextEncoder().encode(canonicalJson) 生成精确 UTF-8 字节流；

对该字节流计算 SHA-256 作为内容摘要 digest；

生成独立的单调序号 event_id。

分级落盘契约：

关键生命周期事件（QUEUED、开始意图、STAGED、ONSET、首次合法有效触控输入、会话终止）：必须在状态转移前完成本地事务落盘，落盘成功方可驱动状态机进入下一阶段。

非关键时序遥测块（如连续滑动触控轨迹、逐帧调度抖动）：采用有界微批次（Micro-batching，如每 20 帧或单个 Trial 结束时）聚合为一个 Telemetry Block 写入本地存储；在块头显式声明 pending_flush_window，并在组任务结束前发起一次强制全量核对。

失败边界：严禁将“本地事务落盘”延后至整个实验结束；严禁为了等待服务端网络 ACK 而延长当前 Trial 的刺激显示或 ISI。

验证场景：在浏览器模拟断电（直接强制关闭标签页），检查本地 IndexedDB 中最后一条记录是否完整停留在前序已落盘的确定状态，且摘要校验无损。

落实阶段：P0 级落实。

5. 本地存储架构：主线程 IDB vs Storage Worker

评估与对比：

使用专职 Storage Worker 虽可将 IDB 操作移出主线程，但主线程与 Worker 之间传输大量时序数据必须依赖 postMessage 结构化克隆（Structured Clone），其在移动端引起的序列化 CPU 开销和内存拷贝延迟往往高于 IDB 底层本身的异步 I/O。

现代浏览器的 IndexedDB 引擎底层已在独立的浏览器 I/O 线程中执行磁盘操作，主线程仅承载极短的回调派发。

推荐方案：首版采用主线程 idb 异步封装，实施“双表同事务”原子写入。

创建同一数据库下的两个 Object Store：event_records（原始持久记录）与 outbox（待同步队列）。

每次写入必须在同一个 IDB Transaction（readwrite）内完成两表写入，只有在 tx.oncomplete 事件触发后，内存状态机才将该事件确认为 LOCALLY_SAVED。

时序任务组执行期间，完全切断任何网络上传；仅在问卷阶段、组间休息或会话结束封印（SEALED）时，启动带抖动（Jitter）的有界离线同步上传器。

失败边界：若 IDB 写入遭遇配额超限（QuotaExceededError）或存储损毁，状态机立即阻断后续刺激呈现，弹出不可恢复错误提示并保留内存诊断信息。

验证场景：在模拟存储接近满额（通过 Chrome Storage Quota 限制）的场景下，验证 IDB 写入事务失败时状态机的快速熔断行为。

落实阶段：马上可落实。

6. 图片解码预算与双阶段门控流水线

解码内存物理法则：

解码显存占用=像素宽度×像素高度×4 字节 (RGBA)

一个 200KB 的高压缩比 JPEG 图片，若分辨率为 8000×8000，解码后将瞬间吞噬 256MB 内存。按文件大小（KB）做内存控制是完全无效的，必须以像素总量作为预算基准。

推荐方案：

客户端双阶段隔离门控：

下载阶段：限制最大并发请求数（如固定 4 个连接），流式拉取并比对原始 SHA-256 摘要；

解码阶段：使用 HTMLImageElement.decode() 或 createImageBitmap() 执行离屏解码，并放入常驻内存引用表；

真实性声明：解码成功仅代表位图就绪，不承诺 GPU 驱动层永不发生显存置换（Eviction）。

失败边界：组内所需的 50–100 张素材中，只要有任意一张下载超时、摘要不符或解码崩溃，门控严禁放行，会话终止在准备阶段。

验证场景：构造带有 1 张超大分辨率（10000×10000）图片的实验配置，验证服务端上传拦截与客户端在内存受限设备上的解码保护。

落实阶段：P0 级落实。

7. 静态素材深度格式校验：防范动态与伪造格式

安全隐患：

部分 PNG 包含 acTL（动画控制块），本质是 APNG 动态图；

部分 WebP 文件在 VP8X 扩展块中设置了 Animation 标志位，并包含 ANIM/ANMF 数据块，属于动态 WebP；

攻击者或误操作可能上传重命名为 .png 的恶意 HTML/SVG 文本文件。

推荐方案：服务端采用轻量二进制结构解析器（严格文件头与关键 Chunk 校验）。

PNG 校验：验证文件头 8 字节魔数（89 50 4E 47 0D 0A 1A 0A）；顺序扫描 Chunk，提取 IHDR 的像素宽高；若扫描到 acTL Chunk，立即判定为非法动画 PNG，拒绝入库；直至遇到 IEND 确认结构完整。

WebP 校验：验证 RIFF 容器头与 WEBP 标识；读取 VP8X 头；若检测到 Flags 中的动画位（Animation Flag, bit 1）置位，或存在 ANIM Chunk，立即拒绝。

JPEG 校验：验证 SOI（FF D8）到 EOI（FF D9），解析 SOF0/SOF2 标记提取基线/渐进式帧尺寸。

失败边界：禁止在生产请求路径中调用重型图像处理库进行服务端动态转码；校验不合规文件直接在暂存区抛弃，不进入硬链接发布流程。

验证场景：准备一组测试文件集：合法 PNG、合法 WebP、带有 acTL 的 APNG、动态 WebP、伪造后缀的 HTML 文件、末尾截断的损坏 JPEG，验证校验器的拦截准确率。

落实阶段：马上可落实（可基于纯 TypeScript 编写无第三方依赖的二进制检查模块）。

8. 私有资产网关、缓存策略与反向代理职责

推荐方案：

网络拓扑与反向代理：前置反代（Caddy/Nginx）仅负责 TLS 终结与证书管理，通过 Loopback TCP（127.0.0.1:PORT）将流量转发给 Fastify。

静态与私有资产完全隔离：

公开前端资产（带 Content Hash 的 JS/CSS）：由反代或 Fastify 托管，响应头设置 Cache-Control: public, max-age=31536000, immutable，启用预压缩（Gzip/Brotli）。

HTML 页面入口：设置 Cache-Control: no-cache。

动态 API 接口：设置 Cache-Control: no-store。

私有实验图片（Research Assets）：绝不映射为公开静态目录。客户端必须通过 /api/assets/:hash 端点拉取，请求需携带合法会话 Token；响应头设置 Cache-Control: private, no-transform, max-age=86400 与强 ETag。针对多被试共用同一物理设备的场景，在会话生命周期结束时，客户端通过 Cache API 显式清除该会话相关的缓存条目。

日志精简：关闭静态素材 200 状态码的逐请求日志；保留 4xx/5xx 错误日志与接入层结构化审计日志。

失败边界：任何未携带凭据直接请求私有刺激素材的连接，一律返回 403 Forbidden。

本方案为验证单机 2 核 / 2–4GB 服务器在 20 名被试并发运行下的鲁棒性而设计。所有数值指标均为 TEST_ONLY 候选验证基准，不作为系统已达标的推断依据。
