## 已确认的问题

### 1. 熟悉度题没有提供可识别的评价对象

正式流程实际为：隐藏照片 → 询问熟悉度 → 提交熟悉度 → 显示照片 → 五项印象评分 → 年龄 → 清屏约 3 秒。

熟悉度题是“在观看本张照片之前，您对这位医生有多熟悉？”。此时照片画布被清空并设为隐藏，页面也没有医生姓名或其他身份线索。参与者无法判断“这位医生”是谁。20 张照片的熟悉度阶段全部如此；前一张的照片也已经清除。

运行器将该盲答数值绑定到随后出现的照片。绑定和保存虽然一致，回答的解释却不成立。知情同意书同样写了“每张照片呈现前”评价熟悉度，因此需要同时调整文书和正式流程。

建议：先显示当前照片，再询问“在参加本研究之前，您对照片中的这位医生有多熟悉？”，随后进行五项评分和年龄估计。这样仍然询问既往熟悉度，参与者也能识别评价对象。如研究确实要求照片出现前回答，则必须另外提供有效的医生身份线索。

证据：`.local/doctor-logic-check-20261019/familiarity-without-photo.png`、`full-report.json` 的 20 条 `familiarity_photo_hidden: true`；生产运行器 `run-eQfSL_g3.js` 的熟悉度阶段调用清屏函数后才显示问题。

### 2. “导出问卷结果”没有医生评分

`answers.csv` 仅展开普通问卷页，当前版本只有手机号题。因此该文件有会话信息和手机号，没有熟悉度、五项印象或年龄列。

评分没有丢失。完整导出的 `data.csv` 在 `table=trial_results` 的 JSON 中包含它们，已逐项核对 140 个值与输入一致，`replay_error=null`。但是简化结果 CSV 不适合直接分析本任务，容易让使用者误以为没有保存评分。

建议为照片评分提供独立、每张照片一行的结果表，至少包含会话、版本、照片编号、类别、呈现顺序、熟悉度、五项印象、年龄、完成状态及时间指标。当前应使用完整数据导出读取评分。

### 3. 管理端模拟与正式作答不一致

模拟会正确抽取 20 张照片，但只呈现第一项印象题及 9 个选择按钮，并通过“上一张／下一张”翻照片。它没有模拟熟悉度、其余四项印象、年龄输入和正式的逐题必答流程。

建议让模拟复用正式任务的题目状态机，并将写入替换为内存保存。当前模拟只能检查照片及部分布局，不能作为正式流程验收依据。

### 4. 知情同意书与采集字段的描述不一致

同意书称“除……手机号外，不保存其他可以识别受试者身份的信息”。实际服务端保存 `request.ip`、浏览器请求信息；客户端还保存设备／屏幕／浏览器环境。当前协议没有设置 `record_interactions=false`，所以默认记录交互轨迹和页面状态。

在隔离答卷的完整导出中已确认这些字段存在。这些记录可用于质量检查，但文书应准确说明采集范围及用途，或相应缩减采集。不能仅按“只收手机号和评分”理解当前设置。

## 需要确认的使用设置

- **电脑端方向限制**：`orientation=portrait`。1280×800 的普通横向电脑窗口显示“请将设备调整为竖屏”，主页面不可操作；调成纵向窗口后可以继续。这是方向门禁，并非屏幕分辨率读取失败。若需要电脑正常横向作答，需要调整支持方向及相应布局。
- **中断规则较严格**：作答时改变窗口／可见视口、隐藏页面会终止本组；帧间隔超过 100 毫秒也会触发中断。另有 120 秒无操作、300 秒连接中断的超时规则。窗口变化的中断已实测，其余为当前运行器规则核对。是否适合自定步速的评分任务，需要结合研究要求确定。
- **年龄允许 0–120**：技术上与配置一致，但允许 0 岁等值。若研究只接受成年医生的合理年龄估计，需要另定范围；本次没有修改。
- **模式为 TEST_ONLY**：当前不是 `COLLECTION` 模式。正式使用前需确认计划采用的采集模式和设备要求；本次没有切换。
- **时间指标的含义**：`rating_item_times[*].first_rt_ms/last_rt_ms` 均从本张照片首次呈现计时，不是从每一道印象题出现时计时；年龄没有单独的题目反应时。分析时不能直接把这些字段解释为单题阅读／决策耗时。
