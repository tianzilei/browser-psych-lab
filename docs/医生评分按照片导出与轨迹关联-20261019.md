# 医生评分按照片导出及轨迹关联

2026-10-19，北京时间。问卷结果以每位受试者对每张照片一行为主表，并在评分、操作轨迹和回放中明确标注具体照片。

## 导出设计

“导出问卷结果”默认下载 `ratings.csv`。管理端下载链接明确标注“每张照片一行”，原来的手机号问卷表改标为“受试者信息”，避免与评分主表混淆。

一位受试者完成 20 张照片时，评分表包含 20 行；两位完成时为 40 行。每行包括照片编号、照片文件名、完整来源路径、类别、该受试者的呈现顺序、资源编号、图片摘要，以及五项印象、熟悉度和年龄。会话编号用于区分不同受试者，照片编号用于区分评价对象；呈现顺序不替代照片编号。

关键列：

| 列 | 含义 |
| --- | --- |
| `session_id` | 本份受试者答卷 |
| `photo_id` | 稳定照片编号，例如 D229 |
| `photo_filename` | 原图片文件名，例如 D229.webp |
| `photo_path` | ZIP 包名及图片路径 |
| `photo_category` | 性别／是否戴眼镜的分层类别 |
| `photo_order` | 本份答卷中实际呈现的第几张 |
| `asset_id` / `photo_hash` | 资源标识及图片 SHA-256 摘要 |

当前空表模板为 37 列，见[医生照片评分模板.csv](../examples/exports/医生照片评分模板.csv)。导出说明声明评分主表为 `ratings.csv`，布局标识为 `one-photo-per-row-v2`。中断及不完整记录仍保留状态标记，不会被标记为正常完整回答。

## 轨迹与回放

新运行器在每次评分事件及交互上下文中直接保存照片编号、文件名、路径、类别、顺序和资源标识；另记录当前评分题和照片是否可见。清屏间隔使用间隔阶段标记，避免把等待中的操作描述为正在评价照片。

轨迹 JSON 增加本份答卷的 `photos` 索引，来自该答卷实际许可方案与资源元数据。旧轨迹可使用已有的 `instance_id`／`asset_id` 关联原照片，无需改写原始字节或原始哈希。在线与离线回放在状态栏显示照片文件名及呈现顺序，详情中显示照片信息。完整数据中的派生轨迹表也包含照片标识。

受试者信息页上的操作没有照片归属；无法唯一匹配或标识冲突时不猜测照片。离线轨迹中仍保留原始事件和 SHA-256 校验。

## 验证

- TypeScript、生产构建和 194 项单元测试通过。
- 7 项针对性浏览器回归通过，涵盖评分事件／交互的照片信息、补充题顺序与模拟流程。
- 使用当前发行物及相同照片库，在隔离数据库中保留一份旧答卷并新增一份完整答卷。两份各 20 张，评分导出共 40 行；280 个答案、40 个文件名、来源路径、摘要与呈现顺序全部匹配。
- 新轨迹 2,331 个、旧轨迹 2,411 个照片关联动作逐一核对，合计 4,742 个；原始事件哈希全部一致。
- 在线和下载的离线 HTML 均能在熟悉度阶段显示正确照片文件名；管理端按钮自动下载按照片排列的结果，受试者信息下载链接独立。
- 线上复查确认运行器及管理、回放、正式评分入口为新发行物，协议与测试定义一致。没有创建生产测试答卷。
