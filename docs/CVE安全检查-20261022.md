检查对象：本地提交 `7697a80967dcaf5c5c5893b2928a991005229dcd` 的源码、锁文件、已安装依赖和部署模板。公告查询截至 2026-10-22（Asia/Shanghai），重点核对近期与本项目技术栈有关的公告，并检查历史漏洞的版本范围。

**修补后的基线：Node.js 24.22.1、npm 11.19.1、Fastify 5.12.7。** 项目版本文件、engines 和依赖锁文件已同步，原生 SQLite 驱动可加载。该版本已于 2026-10-22 部署生产 ECS；Caddy 也已更新为使用 Go 1.27.3 构建的 2.11.7，处理另行核对的 CVE-2026-111943。详见 [安全修补上线记录](安全修补上线-20261022.md)。

## 优先处理：Node.js 高危版本命中

以下 4 项的官方严重性均为 High，修补目标为 Node.js 24.22.1。[Node.js 2026-10-21 安全公告](https://nodejs.org/en/blog/vulnerability/october-2026-security-releases)、[24.22.1 发布记录](https://nodejs.org/en/blog/release/v24.22.1)。

| CVE | 官方描述摘要 | 本项目触发条件核对（本地代码分析） |
| --- | --- | --- |
| CVE-2026-111497 | Brotli 解码越界写，可导致代码执行 | 存在真实 Brotli 解压调用，但输入为本地发行构建产物；未发现公网上传进入该解码器的路径。详见下文。 |
| CVE-2026-105482 | `dns.resolve` 对含 NUL 的名称处理异常 | `src/server` 未发现直接调用 `dns.resolve`，也未发现公开 API 接受用户提供的主机名并交给该接口解析。版本仍需修补。 |
| CVE-2026-105483 | 全角数字 IP 导致 TLS 主机名验证绕过 | 服务端业务代码未发现用户可控的出站 HTTPS 目标；运维备份脚本的目标由受保护环境变量提供。 |
| CVE-2026-106069 | 非规范 IP 表示导致 TLS 主机名验证绕过 | 同上。入站 HTTPS 服务本身不等于调用了受影响的出站证书主机名校验。 |

Brotli 路径的具体核查：

- `src/server/json-transport.ts:28` 只允许指定 POST 路由使用 gzip；`Content-Encoding: br` 返回 415。图片 ZIP 使用 `inflateRawSync` 解码 Deflate，并不使用 Brotli。
- `src/server/release.ts:43` 在启动保留运行器时调用 `brotliDecompress`，输入来自本地 `dist/web`，解压前核对压缩文件哈希，解压后核对原文件摘要；`scripts/release.mjs:17` 在构建时也调用 Brotli 解压。
- 因此，攻击者若只能提交公开问卷请求，当前未发现其能够控制上述解码输入。若发行目录或构建供应链被篡改，需重新评估；哈希和 `maxOutputLength` 不能替代原生解码器的安全补丁。
- `scripts/backup.mjs:3` 的 Node `fetch` 默认访问 loopback HTTP，目标可由 `BACKUP_API_ORIGIN` 改写。外部目标、重定向及响应解压属于运维配置相关路径，本次未在生产环境验证。

上述触发分析为源码推断及既有测试验证，不是利用成功证明，也不改变官方的组件严重性。

## 次要处理：Fastify 低危版本命中

[CVE-2026-107832 / GHSA-389g-gv7q-r4x8](https://github.com/fastify/fastify/security/advisories/GHSA-389g-gv7q-r4x8) 于 2026-10-13 公布，Low，CVSS 3.1 为 3.7。受影响范围为 `>=5.12.2 <5.12.6`，修补版本为 5.12.6。检查时项目锁定 5.12.5，属于版本命中。

该问题涉及请求头 schema 中 `propertyNames` 的大小写归一化。检查 `src/server` 未发现使用此类 schema；当前 Origin、Cookie 和 CSRF 检查直接读取请求头，见 `src/server/lab-routes.ts:31`。据此判断，当前应用未发现此公告的触发配置。建议随维护升级 Fastify 至 5.12.6 或同一主版本中更高的已修补版本。

初次 npm 和 OSV 查询均未报告此项，原因未核实；以上判断采用维护者公告和实际使用方式。

## 建议的修补顺序

1. 优先将开发、构建及生产 Node.js 统一升级到 24.22.1 或同一 24.x 分支中更高的已修补版本；同步 `.nvmrc`、`.node-version`、package / lock 中的 engines 最低版本和当前环境文档。`scripts/doctor.mjs:16` 严格比较 `.nvmrc`，只升级可执行文件会造成该检查失败。
2. 将 Fastify 升级到至少 5.12.6，并更新锁文件。
3. 在新 Node 下按锁文件重新安装，验证 better-sqlite3 原生模块可用，运行项目要求的 `npm run check`。初次检查的 10 项测试是旧运行时下的防护验证，不能替代升级后的完整检查。
4. 部署时核对 systemd `ExecStart` 实际指向的 Node 可执行文件，并重启应用及使用 Node 的备份作业，避免仅更新交互终端中的 Node。
