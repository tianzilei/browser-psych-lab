# Gemini 交互代码审计与修复

2026-10-11。用户要求使用 Gemini Bridge 审计交互代码并优化逻辑与实现。初始工作区干净，基线提交为 `a92395754ebed41a56261ee6c7c71f74c507bc7a`。本轮聚焦参与者问卷、评分与固定刺激任务、准备/恢复、IndexedDB 保存链路和交互诊断；管理端及服务端完整审计不属于本轮逐文件覆盖。

[Gemini 会话](https://gemini.google.com/app/915717d27a627573)。提供了 33 份源码、样式和测试的 15 段连续输入，再完成方案收敛、5 段实施差异输入及最终静态复审。完整输入、返回、文件摘要和请求身份保存在本目录。

| 场景 | 修复与验证 |
| --- | --- |
| 可选个人信息题填写后删空，仍被格式正则挡住 | 空值遵循共享 `answerMissing` / 服务端规则；非空错误格式仍阻止继续。新增浏览器测试先失败、修复后通过。已卸载问卷也不再接受晚到的保存和导航事件。 |
| 按住评分滑块，通过键盘进入年龄题后松手 | 保存绑定产生事件的实际评分轴，核验当前轴与可用阶段；切题、提交和中断释放指针捕获。年龄题的 `undefined.dataset` 错误已实际复现；回归同时覆盖跨评分项与跨图片。 |
| 键盘进入下一评分项后焦点丢失 | 键盘激活“下一题”后聚焦下一轴或年龄框，并使用 `preventScroll`；触摸切题维持现行焦点方式。重复的同值评分不再新增 `RATING_CHANGE`，原始输入诊断继续保留。 |
| 等待许可响应期间改变屏幕布局 | 准备和启动的异步断点后检查取消；许可前后及会话刷新后核验可见性与原布局。保留关闭页面的取消监听，向预留/许可请求传入信号。已确认发放的许可在检查失败时尝试终止。布局变化回归先失败、修复后不呈现刺激。 |
| 大量可见 DOM 节点导致诊断屏幕样本超预算 | 完整 JSON 包装加每个节点的 UTF-8 编码长度累计限制为 75000 B，超过即设置 `nodes_truncated`。1200 个控件的回归验证诊断批次在预算内，原始输入值与数据完整保留。 |
| 组封存失败后恢复按钮仍经过任务输入监听器 | `finish` 的异常路径先解绑剩余监听；实际封存失败、按任务响应键、点击重试的回归验证未增加任务输入诊断，正常封存成功。 |
| 原标签关闭后，重复标签无法继续或旧记录不能封存 | 增加手动“重新尝试”。在同版本原生 Web Lock 内恢复本地持久写入者，避免推进 epoch 后让原始旧答案变成历史待核对记录；同步 sessionStorage 供冻结运行器沿用。旧 metadata 从保存的 session 身份迁移，严格事务重读最新 metadata，重答仍归档原答卷。真实双标签回归验证旧答案及 writer/epoch 保留，并完成封存。 |

答案修改仍即时进入原始事件队列，不采用输入防抖、失焦才保存或松手才保存。没有改写已有事件、放宽 ACK/seal、修改服务端所有权策略或改变旧冻结版本的合同。

Gemini 首轮把防抖保存、方向门控持续监听、年龄输入的软键盘行为以及文本失焦视为缺陷。未采用这些建议：防抖违反即时记录要求；方向门控有缓存单例及 pagehide 清理，持续拦截是现行功能；年龄输入为 readonly/inputmode=none，不扩大忽略真实几何变化的范围；文字布局继续由“完成输入”退出，避免失焦移动按钮造成点击丢失。其估计的设备延迟和性能数字没有作为实测结果。

完整检查还暴露了既有诊断测试的错误假设：actions API 按接收 rowid 分页，发件箱 UUID 顺序可能让批次乱序到达，原生点仍全部保留。测试改为核验完整点集及原始字段；生产回放原本就按事件时钟排序。首次检查的一项管理员限流失败发生在失败测试引起 worker 重启、重新登录之后；生产限流未调整。

最终复审返回 `INTERACTION_PATCH_REVIEW_DONE`，未提出新增阻塞。这是模型的静态意见，运行证据以 [validation.json](validation.json) 为准。不得将 Gemini 原文中“可靠闭环”“所有输入绝对不超预算”等扩大表述当作保证：丢失许可响应仍可能产生未知状态，终止请求也可能断网；字节限制针对 DOM 屏幕快照，任意大小的原始输入仍受既有队列与事件预算约束。
