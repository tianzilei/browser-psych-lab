# 自适应问卷与后台自动保存

长问卷采用两层分页：浏览器根据可用视口、完整题干和控件实际高度组成屏幕页，后台同时按最多 30 题和最终答案快照的 128 KiB 字节上限组成不可变保存段。受试者点击“下一页”，存储段结束自动确认保存，没有额外“提交本页”和重复说明。

简化 JSON 配置：

```json
{
  "schema": "questionnaire-v1",
  "questionnaire_layout": "adaptive",
  "record_interactions": false,
  "orientation": "auto",
  "title": "问卷",
  "pages": [{
    "id": "survey",
    "instruction": "请根据实际情况作答。",
    "questions": []
  }]
}
```

将完整题目依原顺序放进 questions，不必手工每 30 题拆段。导入自动产生 survey_part_1 等 scope；题目 ID、题干、量表、编号匹配保持原值。总保存段最多 30，最多 900 题；长文本或长选项可能先达到字节预算，因此可用总题数可能低于 900。导入按所有合法答案的最大 JSON 字节数估算，包含 UTF-8、转义、题号和事件信封开销。长段拆分后只有首段保留说明。显式的多个原始 sections 可以分别保留各自说明。完整 study-v1 使用相同布局字段，但显式 pages 不自动重排，须同时符合每段 30 题和快照字节上限；超限时导入或新发布会拒绝。已冻结版本与原始作答记录不重分段。

自动生成的段 ID 同样不能超过 100 字符，导入时会预先检查最长的 `_part_N` 后缀并提示缩短原 ID，不截断或重命名既有 ID。例如拆成 30 段时，原 ID 最多 92 字符；拆成 2 段时最多 93 字符。

省略 questionnaire_layout 或使用 single 时保持原逐题界面和严格 30 题限制，字段省略仍省略，历史协议哈希不变。orientation:auto 仅适用于 adaptive 的纯问卷，编译后不固定方向；含照片/计时任务仍必须指定原方向。录制轨迹由 record_interactions 独立控制，医生评分保持开启。

## 屏幕行为

手机通常显示 2–4 题，大屏可以使用两列并显示更多题；题数取决于实际题干换行、屏幕高度及保存状态提示，不按手机型号硬编码。字体不缩小；量表沿用现有无默认答案的滑块，触控区域至少 44px。编号输入独占一页。长题和小屏保留完整内容，通过题区滚动完成。题干、量表端点、完整选项与未答反馈保持可读。

本页必答及格式校验通过才翻页。未输入不记默认中点；IME 组合期间不翻页。文字输入聚焦及键盘缩小视口时保留当前题目，失焦或其他尺寸变化重新测量，当前首题为锚点。上一页可检查当前尚未确认的保存段，段结束快照后禁止返回该段修改。说明明确告知这一点，保存段不跨屏幕页混排。

## 保存行为

每次改变答案立即进入严格持久化 IndexedDB 事务，700ms 防抖触发后台上传。屏幕翻页等待本机提交完成；网络上传不阻挡进入下一段。按服务器 page_index 过滤上传 scope，后一段只能在前一段 seal 后上传。INPUT_DIAGNOSTIC 可独立上传；关闭轨迹时不创建这些事件。

只有一个后台上传拥有者。触发发生在上传期间会合并成下一次检查，避免并发 ingest/seal。重试保留原始事件/请求/manifest 身份。seal 响应丢失时，从服务器取回并严格验证同一封存凭证，不重新创建快照。未修改服务端语义、冻结数据、已有答卷、原始字节与哈希链。

正常作答时隐藏“本机已保存／后台同步／已同步至服务器”等常规提示及其占位，避免每次输入改变提示和布局，也不向读屏软件播报这些状态。后台的本机提交、上传和服务器确认照常执行。断网、重试、容量提醒和最后的完成确认仍可见。

断网继续本机作答；连接失败按 15、30、60 秒退避，准入满额或等位至少间隔 60 秒。异常提示显示下次自动尝试时间，点击“重试保存”或联网事件立即触发一次检查。连接续约失败不会销毁表单，上传前恢复准入。重新加载需要页面资源及连接可用后恢复，IndexedDB 保存答案、首题游标和上一页位置；未完成段保留。离线关页不能保证浏览器替用户继续上传；应使用同一浏览器恢复，并等待最终保存确认。

本页没有常驻 WebSocket 或持续查询保存状态的轮询。无操作时仅每 60 秒续约一次准入；答案改变后按现有 700ms 防抖上传，上传拥有者保持互斥。本次隐藏提示不改变这些请求、保存段、重试频率或数据预算。

恢复时先采用服务器已封存的规范答案，再按顺序对本机已快照但尚未封存的段执行共享 `pageSnapshot` 归一化。条件隐藏的旧答案在恢复投影中为 null，避免重新触发已跳过的后段。未快照的当前段仍恢复可编辑草稿。原始事件、草稿、manifest 与哈希保持原值；本机 pending 路径与规范路径冲突时保留记录并提示研究者处理，不擅自重写已有证据。

“完成问卷”先在本机存下最后快照，再等待所有段封存和服务器 finalize，成功后才显示结束页。等待阶段显示服务器已确认的段数百分比及重试时间；即使封存达到 100%，finalize 尚未成功时仍显示“完成状态尚未确认，请保留页面”。百分比按服务器保存位置计算，包含服务器已跳过的条件段。管理页模拟采用相同自适应渲染，不写真实答卷。

## 同段大量修改的容量保护

每次有效改答都会累积 revision，30 题不等于固定 31 条事件。adaptive 问卷按完整 UTF-8 事件字节统计当前段，旧本机元数据缺少计数时从保留的原始记录重建；已上传事件仍计入累计量。

服务端原有上限为每段 5000 条事件、32MiB，单条事件最多 128KiB。达到 4500 条或 31MiB 时显示核对提醒；继续修改前预留一条完整 128KiB 的最终快照。超出可编辑容量的修改在写入前拒绝，不删旧事件、不截断答案、不改变哈希链，并保留已提交的草稿。拒绝修改不会使本机写队列永久失败；重新恢复时可查看并提交已保存且校验通过的答案。若尚有必答题未完成，需要研究者处理，预留快照不能绕过必答或字符匹配校验。

## Gemini 讨论采用情况

[Gemini Bridge 原文](gemini自动分段与存储/自适应分页-Gemini讨论.md) 建议独立呈现/上传队列、scope 栅栏、输入时稳定布局、当前段内回退、最终封存屏障，本实现采用这些设计。配置简化为枚举；真实 DOM 测量替代按字数估算；保留原滑块，没有采用数字按钮改造。保存提示没有声称客户端加密。讨论建议本身不作为测试通过证据。
