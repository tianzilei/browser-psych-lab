# ECS 并发与空闲中断（2026-10-11）

对 example.invalid 的同一台 ECS（2 vCPU、1735 MiB RAM）建立独立进程、独立数据库，并复制只读生产图片进行公网 HTTPS 压测。没有向生产数据库写压测答卷。压测结束恢复 Caddy，停止测试进程，保留测试数据库和报告。

每个会话随机下载 32 张实际医生 WebP，生成 32 轮六项评分与年龄的合成回答，补传 5120 个动作（约 2.09 MB），经过真实 SQLite FULL 持久化、服务端重放、封存和完成流程。手机渲染与物理反应时间不属于此压测。

通过标准：所有会话完成且图片摘要一致，下载 p95 <60 秒，普通控制请求 p95 <2 秒，封存 p95 <30 秒，过载响应比例 <1%，进程 RSS <500 MiB。单例、2、4、8、12 初次通过；13、14、16 未全部完成，12 复测也出现超时。9 人降档验证通过，7 人最终验证通过。因此采用 9 人作为本工作负载的容量参考，floor(9×0.8)=7 人作为运行上限，不将这个数称为服务器的理论最大并发。

最终 7 人：下载 p95 24.69 秒，控制 p95 477 ms，封存 p95 1.00 秒，全部完成，无过载响应，RSS 226 MiB。原始波次见 [ecs-capacity-2026-10-11.json](ecs-capacity-2026-10-11.json)。

图片/定时任务的会话准入与图片准备都设为 7。纯問卷（无 groups）不占用此名额。满额立即返回 HTTP 409 和 Retry-After: 1800，界面提示建议30分钟后再进行答题；不创建等待票据、不轮询等待、不自动放行。现有有效会话不因满额被踢出。历史排队条目改为 LEFT，历史答案保留。

新版本任务采用 `idle120-offline300-v1`：客户端连续120秒无实际指针、键盘或输入操作即中断；活动期间每60秒最多发送一次小型 `/activity` 请求，失败不阻塞评分。服务端记录接收时间，连续300秒无成功续租自动终止并关闭未知 permit、释放名额；全服务器共用每30秒一次索引扫描，因此服务器关闭可能在300–330秒发生。短时断网继续本地保存；重连后终止会话仍能补传原始数据，不能封装成正常完成。客户端感知连续300秒无法确认续租也会停止。

任务策略纳入不可变 runner contract。历史版本继续原冻结合同，新版本开启上述策略，服务端不信任客户端去掉 activity_policy。纯问卷不使用空闲中断。任务刷新后自动关闭未知运行并核对保存记录，无需额外中断确认。无需增加挂起状态。

下载前显示预计大小（抽样32张按全部候选图片的平均字节估计，实际大小略有差异）；下载过程仅显示百分比。年龄输入为只读显示框加页内数字键盘，禁用系统输入法；支持实体键盘数字与退格。评分轴通过 pointer capture、pointermove、pointerup 显式更新，以支持移动端拖动。
