### 一、 架构与交互模型审查

#### 1. 视口锁定与防滚合同（No-Scroll Guarantees）

- **触屏与手势冒泡风险**：
  - 单纯在 CSS 设置 `overflow: hidden` 并不能阻止移动端 Safari/Chrome 的原生橡皮筋弹性滚动（Overscroll）以及双击缩放。
  - **必防边界**：
    1. 根容器设置 `touch-action: manipulation`（或针对非输入区域设置 `touch-action: none`），严禁手势缩放；设置 `overscroll-behavior: none`。
    2. 针对非输入区域的 `touchmove` 事件，在必要时调用 `event.preventDefault()`，防止浏览器默认的视口拖曳。
- **`100dvh` 与键盘弹起的冲突**：
  - 当文本题聚焦、软键盘弹出时，移动端浏览器的 `dvh`（Dynamic Viewport Height）表现不一（部分浏览器 `dvh` 会随键盘缩减，部分则保持不变而仅由 `window.visualViewport` 改变高度）。
  - **合同断言**：在有文本输入激活时，**布局基准高度必须切换绑定至 `window.visualViewport.height`**，而非静态的 `100dvh`；键盘收起后恢复为 `100dvh`。

### 二、 长文本与长选项分页（Pagination via Binary Search）

#### 2. 分页切分算法的真实陷阱

- **DOM 测量二分切分的重排颠簸**：
  - 题干最长 1000 字符、说明最长 8000 字符。如果每次尺寸变化都在同一个容器中反复设置 `textContent` 并调用 `scrollHeight > clientHeight` 进行二分查找，会触发数十次同步重排（Reflow）。
  - **实现要求**：
    1. 必须使用一个脱离文档流的隐藏测量沙盒（`visibility: hidden; position: absolute; pointer-events: none`），限定确切的可用宽高，在该沙盒内进行二分逼近。
    2. 必须处理字符分词与 Unicode：不可仅用字符索引切断，必须优先在换行符 `\n` 或标点边界切割；严禁切断 UTF-16 代理对（Surrogate Pairs，如 Emoji）或组合字符序列（Combining Characters）。可利用 `Intl.Segmenter`（按 `grapheme`）或安全的字符边界检查回退。
- **分页状态与题目导航的层级混淆**：
  - 若一道题的题干分为 3 段展示，选项又分为 2 页展示，页面上同时存在“下一段”、“下一组选项”、“下一题”，参加者极易混淆自身所处流程。
  - **状态机规范**：
    - 采用嵌套游标：`questionIndex` $\rightarrow$ `readingPageIndex` $\rightarrow$ `choicePageIndex`。
    - **严格单向下推**：题干未读到最后一段前，不显示选项区域（或选项置灰且主操作按钮为“阅读下一段”）；只有题干阅读完毕，操作主按钮才切换为“下一组选项”/“下一题”。
    - 长选项（如 200 字符）点击进入“详情模态全屏/独立视图”后提供“确认选择此项并返回”按钮，避免在紧凑的选项网格中文字被截断。

### 三、 键盘输入法（IME）与 VisualViewport 适配

#### 3. 软键盘弹起时的视口挤压

- **空间不足与“不滚动”的逻辑死锁**：
  - 移动端横屏或极小屏幕下，软键盘弹起可能占据屏幕高 60%~75%，剩余 `visualViewport.height` 可能仅剩 150px 左右。
  - 在 150px 空间内，如果同时容纳：页眉、输入框、报错信息、底部“下一步”操作按钮，会导致**任何一个常规大小的控件都排不下**，而此时“禁止滚动”会导致输入框或提交按钮被裁切出可视区，用户无法操作。
  - **修复方案**：
    - 当 `visualViewport` 高度低于特定阈值（或发生文本聚焦时）：
      1. 临时折叠/隐藏顶栏与标题，仅保留极简题干（1行省略）、原生文本输入控件与紧凑的键盘收起/确认栏。
      2. 遵守“不自动 focus”合同：用户必须显式点击输入框才弹起键盘；输入完成提供显式的“完成/收起键盘”按钮，用户确认后将焦点 `blur()`，视口尺寸恢复后再点选导航。

### 四、 题目导航、分支依赖与误触/重复提交防范

#### 4. 前向/后向分支状态一致性

- **依赖回溯污染问题**：
  - 规则规定“上一题保留答案，分支改变更新后续导航”。
  - 场景：用户在 Q1 选了 A，Q2 为关联题目并作答了 B；随后用户点击“上一题”回到 Q1，将答案改为 C（此时 Q2 条件不再满足，应处于隐藏态）。
  - **数据合同保证**：
    - Q1 变更时立即触发 `visibility()`，Q2 的 DOM 及逻辑状态被标记为 hidden，`effective[Q2]` 重置为 `null`。
    - 当用户在 Q1 点击“下一题”时，导航计算器必须**跳过所有 hidden 题目**，直接定位到 Q1 之后的下一个 `visible === true` 的题目，不得将用户带入隐藏的 Q2。
    - Q2 的用户输入值在内存中继续保留（满足“隐藏草稿保留”），若用户再次返回 Q1 并切回 A，Q2 重新 visible，原答案 B 恢复展现。

#### 5. 提交防重与异步屏障

- **末题提交竞态**：
  - 移动端连击可能在微任务尚未完成时派发多次 `submit` / `click`。
  - **实现要求**：
    - 首次触发“提交本页”时，立即同步设置本地锁 `isSubmitting = true`，并将提交按钮置为 `disabled`，阻止后续任何点击事件。
    - 在发出快照并等待异步持久化前，不可解除锁定；若报错恢复，解除锁并展示可达的错误描述。

### 五、 无障碍（a11y）与大按钮交互

- **大按钮与单选/多选的语义转换**：
  - 将 Radio/Checkbox 转化为“大按钮卡片”时，内部底层必须依然是语义化的 `<input type="radio">` 或 `<input type="checkbox">`，外层包裹 `<label>` 或通过 `role="radio"` / `role="checkbox"` 与 `aria-checked` 映射。
  - 键盘导航（Tab / 箭头键 / 空格键）必须完全可用，不能因写成 `<div>` 或自定义触摸事件而丢失焦点环（Focus Ring）与无障碍树通信。
- **屏幕阅读器焦点路由（Focus Management）**：
  - 由于是一题一屏切换，点击“下一题”时，焦点必须主动转移至新屏幕的顶层 `<legend>` 或主标题（通过设置 `tabIndex="-1"` 并调用 `.focus()`），禁止焦点残留在已隐藏的旧按钮上导致屏幕阅读器失焦。

### 六、 图片任务 Geometry 与准备页合同

#### 6. 准备页与刺激阶段的无缝切换

- **底部栏位稳定性**：
  - 拟方案中“图片准备页将‘开始本组’纳入固定底部，不把按钮 prepend 到 stage 造成几何变化”完全正确。
  - 准备阶段的提示文字和“开始本组”按钮必须占据固定预留的高宽插槽，点击后该区域平滑交出控制权（或销毁/隐藏），**严禁使 Canvas 所在的容器发生哪怕 1 像素的尺寸或位置偏移**。
- **Canvas 几何冻结与中断守卫**：
  - Canvas 的逻辑像素与物理渲染像素比（`devicePixelRatio`）必须在进入试验组前完成最后一次锁定。
  - 刺激呈现期间，任何 `window.onresize`、`visualViewport.onresize`、`document.visibilitychange`、甚至是设备方向改变（Orientation Change），必须**立即执行安全中断（Abort/Interrupt）并终止该 Trial 数据的有效性记录**，绝对不在刺激过程中做任何重排或动态适应。
