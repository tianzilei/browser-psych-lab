## 1. 设计范围与核心原则

### 1.1 适用范围

- 受试者问卷：单选、多选、单轴／多轴量表、个人信息输入、手机号键盘。
- 医生图片评分：评分量表、熟悉度单选、年龄估计输入。
- 配套控件：导航、校验和保存反馈。
- 管理端绿色主题、JSON 上传表单与开发检查页使用各自的样式。

### 1.2 核心原则

> **中性呈现**：使用纯色背景和原生 DOM。选中态采用前景／背景反色；在灰色与深色预设中保持黑白关系，不用红绿渐变、表情、奖惩颜色或中点高亮暗示答案好坏。
>
> **显式作答**：初始不预选。只有明确的点击、拖动或选择键操作才形成答案，单纯获得焦点不写入答案。
>
> **信息完整**：题干、选项、量表标签和研究者自定义文案完整呈现；不通过缩字、省略号或仅 hover 可见的方式隐藏内容。
>
> **冻结与几何约束**：正式背景、数值范围、标签和答案语义遵循冻结协议。评分任务在开始前完成几何测量，运行中不因样式或状态变化移动控件。已有冻结版本与记录保持原合同。

## 2. 视觉基础

### 2.1 颜色令牌

| 令牌 | 灰色预设 | 深色预设 | 对比度（灰／深） | 目标用途 |
| --- | --- | --- | --- | --- |
| `--q-bg` | `#e5e5e5` | `#202020` | — | 页面背景，默认控件内部透明 |
| `--q-fg` | `#000000` | `#ffffff` | 16.67 / 16.29 | 题干、答案、选中填充、焦点与轨道 |
| `--q-muted` | `#535353` | `#c2c2c2` | — | 提示、进度与非关键元信息 |
| `--q-border` | `#787878` | `#8c8c8c` | 3.50 / 4.85 | 可操作控件边框 |
| `--q-divider` | `#b4b4b4` | `#606060` | — | 题卡分隔等非交互结构 |
| `--q-error` | `#9d2424` | `#ffb4ab` | — | 错误文字、错误边界与“清空”键文字 |
| `--q-hover` | `#d9d9d9` | `#303030` | — | 精细指针悬停底色 |
| `--q-disabled` | `#777777` | `#a0a0a0` | — | 不可用文字与标记 |

对比度按 sRGB 相对亮度计算，分别相对于同列的 `--q-bg`；仅适用于这两种预设。

> **主题约束**：正式背景由冻结协议决定，不提供主题切换，也不跟随系统深浅色自动变化。样张开关仅用于设计检查。已有自定义背景继续使用 `applyParticipantBackground()`；应用新边框、辅助色和错误色前，须针对该背景单独校核。

### 2.2 字体、尺寸与 CSS 属性速查

| 项目 | 目标属性／值 |
| --- | --- |
| 字体族 | 系统字体栈，含 `PingFang SC`；不加载外部字体 |
| 题干 | `font-size: 18px; line-height: 1.45; font-weight: 500` |
| 控件主文字 | `font-size: 16px; line-height: 1.45; font-weight: 400` |
| 辅助文字 | `font-size: 14px; line-height: 1.5` |
| 进度／必答提示 | `font-size: 13px; line-height: 1.4` |
| 常规触控高度 | `min-height: var(--q-touch)`，`--q-touch: 48px` |
| 单行输入框 | `height: 48px; width: 100%; min-width: 0` |
| 圆角 | `border-radius: var(--q-radius)`，`--q-radius: 10px` |
| 控件边框 | 默认 `1px solid var(--q-border)`；错误 `2px solid var(--q-error)` |
| 盒模型 | `box-sizing: border-box`；错误态切换保持外框宽高 |
| 内边距 | 常规 `padding: 12px`；紧凑布局横向可用 `8px` |
| 同组间距 | `gap: var(--q-gap)`，`--q-gap: 8px` |
| 题干到答案 | `16–20px`，按实际文本布局测量 |
| 题间距 | `16–24px`，空间不足时减少同屏题数 |
| 焦点轮廓 | `outline: 2px solid var(--q-fg); outline-offset: 3px` |
| 轨道／可见滑块 | 轨道 `3px`，滑块 `22px`，透明交互热区高 `48px` |
| 长选项 | `white-space: pre-wrap; overflow-wrap: anywhere`，标记 `flex-shrink: 0` |

基础间距令牌采用 `4 / 8 / 12 / 16 / 24 / 32px`。正文与控件不通过降低字号来挤入视口；焦点轮廓周围至少保留 `5px`，避免被 `overflow` 裁切。

### 2.3 现状差异与迁移约束

| 项目 | 已落地实现 | 兼容规则 |
| --- | --- | --- |
| 控件边界 | 已拆分控件 border 与结构 divider，选中保持反色 | 保留 `--background`／`--foreground`／`--line` 别名 |
| 错误色 | 灰／深错误色与字段错误边界已统一 | 自定义背景计算可读配色，不修改冻结背景值 |
| 字号 | 通用控件与熟悉度 `16px`，帮助 `14px`，元信息 `13px` | 评分紧凑题干使用 `16px / 1.4` |
| 高度／间距 | 常规热区最小 `48px`、同组间距 `8px` | 评分紧凑变体保留 `44px` 热区与局部 `4px` 间距 |
| 圆角 | 按钮、文本框、轴框、列表链接统一 `10px` | 视觉标记与非控件徽标使用各自形状 |
| 令牌作用域 | 生产使用 `ui-tokens.css` 的根令牌，管理端保留独立绿色调色板 | `.q-surface` 展示令牌仍独立，不作为生产覆盖补丁 |

> **评分紧凑变体**：`data-control-variant="rating-compact"` 明确声明轴与数字键的 `44px` 热区、年龄六列两行和 `4px` 键距。高度不超过 `600px` 时，年龄显示框为 `44px`，题干为 `16px / 1.4`，局部间距为 `4px`；主提交按钮仍为 `48px`。所有隐藏题型共同预留空间，准备阶段测量后锁定几何。

## 3. 控件规范

### 3.1 单选与多选

#### 规范定义（Spec）

**视觉与尺寸**

- 单选使用 `18px` 空心圆，选中后显示内实心点。
- 多选使用 `18px` 圆角方框，选中后显示勾号。
- 整行可点击，文字左对齐、完整换行，标记不压缩。
- 选中时背景为 `--q-fg`，文字与标记为 `--q-bg`；尺寸沿用 2.2。
- 元信息显示“必答／可选”；多选另加“可多选”。

**交互与状态**

- 初始未选；选择后留在当前题，由导航继续。
- 必答单选选中后保持一个答案；可选的通用按钮式单选可再次点击清空。
- 多选独立切换，允许全部取消，答案仍按协议选项顺序保存。
- 焦点与选中分别表达，可同时存在。

**DOM 与无障碍（A11y）**

- 通用选项使用 `<button type="button" aria-pressed="false">`；父组用 `aria-labelledby` 关联题干，装饰标记设 `aria-hidden="true"`。
- 按钮式选项：`Tab` 到达，`Space`／`Enter` 选择；方向键、`Home`／`End` 仅移动焦点，不修改答案。
- 原生熟悉度单选：使用同名 `<input type="radio">` 与可点击 `<label>`，通过 `fieldset`／`legend` 或有名称的 `radiogroup` 关联题干。保留原生键盘行为，方向键可移动并选中 radio；不套用按钮组“仅移动焦点”的规则。

#### 现状差异与迁移约束（Migration & Constraints）

- 通用选项已通过共享 `choiceButton()` 输出装饰标记和 `data-choice-type`；多选使用方框与勾号。
- 逐题与自适应页共用方向键焦点移动，自适应题卡独立显示编号、必答／可选和多选提示。
- 熟悉度保留原生 radio。若将来替换通用选项语义，须同时实现分组、选中状态和完整键盘行为，不能只改 `role`。

### 3.2 单轴与多轴量表

#### 规范定义（Spec）

**视觉与尺寸**

- 保留原生整数 `<input type="range">`；范围、刻度、标签及数值方向遵循冻结题目。
- 轨道高 `3px`，滑块 `22px`，交互热区高 `48px`，周围预留焦点轮廓空间。
- 两端文字同等强调，中点不高亮，不使用带倾向的颜色。
- 多轴各有可见标题与独立反馈；窄屏堆叠，宽屏可按实际空间并列，保持协议读序。

**交互与状态**

- 未作答：隐藏滑块，显示完整轨道、端点与“点击或拖动滑块选择评分”。浏览器内部的中间值不写入答案。
- 已作答：明确点击、拖动或选择键操作后显示滑块、所选刻度与“已选择”反馈；`0` 和负分在协议允许时仍是合法数值。
- 反馈保留研究者的逐级 labels 原文；缺少逐级标签的历史题显示明确分值。样张使用“分值 · 标签”演示反馈格式。
- 方向键、`Home`／`End` 调整并作答；`Space`／`Enter` 明确确认当前刻度，单纯聚焦保持未答。
- 可选轴提供“清除选择”，清除写入 `null` 并恢复未答外观；必答轴不提供清除。
- 多轴逐轴保存。`single` 模式要求所有轴完整同屏，空间不足时阻止继续。

**DOM 与无障碍（A11y）**

- 用题干或轴标题命名 range，动态维护 `aria-valuetext`，表达“尚未作答”或当前分值／标签。
- 通过 `aria-describedby` 关联 `<output>`；反馈使用 `aria-live="off"`，保留原生 range 的值播报。
- 拖动时不向全局 `aria-live` 区高频推送每一帧数值，也不重建控件或重新测量布局。

#### 现状差异与迁移约束（Migration & Constraints）

- 当前已有无默认答案、可选清除与原生值反馈；迁移保留其答案和保存语义。
- 常规轴热区已改为 `48px`、轴框 `10px` 圆角；评分轴保留声明的 `44px` 紧凑变体。
- 当前有 labels 的通用量表直接显示原标签，评分任务显示分值与标签；视觉统一不能改写标签、原始数值或旧冻结版本。

### 3.3 个人信息文本输入

#### 规范定义（Spec）

**视觉与尺寸**

- 单行输入框高 `48px`、圆角 `10px`、字号 `16px`。
- 常驻可见 `<label>`；格式说明位于输入框前，placeholder 仅作示例。
- 错误同时使用文字与 `2px` 错误边框；不靠颜色单独传意，外框尺寸保持稳定。

**交互与状态**

- 仅用于 `input_purpose: "personal"`，遵循 `max_length`、`input_match` 和研究者自定义校验文字。
- 初始空值不报错；尝试继续时校验必答与格式，首次报错后随修改更新。
- 页面加载不自动聚焦，不禁用粘贴，不在输入中重建节点。
- IME 组合输入期间禁止导航，保留输入修订、焦点与控件值。
- `single` 模式由“完成输入”先收起键盘，再进行题目导航。
- `adaptive` 模式在输入聚焦或组合输入期间保留当前题卡与焦点，软键盘改变视口时不重排屏幕页；失焦后可重新测量。

**DOM 与无障碍（A11y）**

- `<label for="...">` 与输入 `id` 对应，`aria-describedby` 关联帮助与错误文字。
- 校验失败设置 `aria-invalid="true"`，错误区域使用 `role="alert"`；纠正后清除错误状态。
- 保留原生输入和文本选择行为，长度与格式校验以协议为准。

#### 现状差异与迁移约束（Migration & Constraints）

- 当前已有个人信息用途限制、原生输入、IME 导航锁和输入期间的布局保护。
- 常规输入框已统一为 `48px` 高、`10px` 圆角；可见 label、帮助／错误关联及首次报错后的即时校验已落地。逐题模式在编辑时继续显示可见题干标签。
- 样张参与编号只演示格式校验，不模拟生产软键盘布局，不扩展普通开放文本题。

### 3.4 手机号与年龄数字键盘

#### 规范定义（Spec）

**视觉与尺寸**

- 键位顺序为 `1–9`、`0`、删除、清空；常规键高至少 `48px`、间距 `8px`。
- 数字字号 `18px`，删除／清空为 `14–16px`；仅“清空”键文字使用错误色。
- 手机号采用三列四行。正式评分中的年龄键盘采用已声明的六列两行紧凑变体；独立展示样张另保留常规响应式布局供比较。

**交互与状态**

| 场景 | 手机号 | 照片年龄估计 |
| --- | --- | --- |
| 输入长度／范围 | 取冻结协议 `max_length`／`input_match` | 取 `rating.age_min`／`age_max`，不写死示例范围 |
| 校验时机 | 未完成保留提示，完整或明显非法时提示错误 | 非空且越界立即显示范围提示 |
| 下一步资格 | 格式合法后启用；可选题允许空值继续 | 年龄合法且任务处于可答状态时启用 |
| 编辑操作 | 数字追加、删除一位、清空 | 同左 |

**DOM 与无障碍（A11y）**

- 使用原生文本 input 显示数字，设 `readonly` 与 `inputmode="none"`，由按键受控更新。
- 保留物理数字键与 `Backspace`，键盘按钮为 `type="button"`，键盘组有清楚的可访问名称。
- 输入用可见题干命名，帮助／错误通过 `aria-describedby` 关联；无效时设置 `aria-invalid="true"`。
- 程序化更新沿用现有输入事件与记录路径，不绕过作答、只读或提交锁。

#### 现状差异与迁移约束（Migration & Constraints）

- 正式实现复用 `numericKeys()`；样张独立演示相同键序，不接入生产模块。
- 手机号即时提示与导航资格已接入逐题、自适应和模拟页，仍使用冻结的格式校验与原事件写入路径。
- 年龄按冻结范围即时校验并控制提交资格；保留 `44px` 键高、六列两行及运行前测量，错误提示使用稳定的预留空间。
- 新构建按现有发布流程生成新的运行器资源标识与 `runner_hash`，保留旧冻结资源。后续改变评分网格仍须重新验收，不能把修改 `RUNNER_VERSION` 常量当作完整升级。

## 4. 状态、反馈与导航

### 4.1 状态矩阵

| 状态 | 视觉属性 | 行为与语义 |
| --- | --- | --- |
| 默认 | 透明背景，`1px solid var(--q-border)` | 初始未答，无预选 |
| 悬停 | `background: var(--q-hover)`；仅 `(hover: hover) and (pointer: fine)` | 触屏不依赖悬停反馈 |
| 按下 | `border-color: var(--q-fg)` | 无缩放、位移或动画 |
| 键盘焦点 | `2px` 前景色外轮廓，偏移 `3px` | 聚焦不写答案；可与选中态并存 |
| 已选 | 背景 `--q-fg`，文字与标记 `--q-bg` | 更新 `aria-pressed` 或原生 `checked` |
| 禁用 | 文字 `--q-disabled`，边框 `--q-divider` | 原生 `disabled`，点击与键盘不能改值 |
| 错误 | `2px solid var(--q-error)`，错误文字同色 | `aria-invalid="true"`，错误区域 `role="alert"` |
| 提交中 | 按钮外框尺寸稳定，显示实际等待文案 | 同步锁定防重入，无旋转动画 |
| 只读 | 说明只读原因，保留已有答案数据 | 按重复页面、容量等现有控制器规则限制编辑 |

### 4.2 保存反馈

- “已选择”和“已选择 X 项”仅表示界面响应，不表示服务端保存成功。
- 常规后台同步提示保持隐藏；断网、存储／容量异常和最终确认按现有控制器在页面内显示，不新增弹窗流程。
- 各段封存与最终完成确认成功后，才使用“研究已完成，数据已保存。”；已写入部分记录不等于整份问卷完成。

### 4.3 导航与错误文案

每个导航区保留一个实心主操作，回退用描边按钮。不可回退时沿用既有隐藏／禁用逻辑，不开放已封存保存段的回退修改。

| 模式／场景 | 文案 |
| --- | --- |
| 逐题 `single` | 上一题／下一题／提交本页 |
| 长说明分页 | 阅读下一段 |
| 文字输入编辑中 | 完成输入 |
| 自适应 `adaptive` | 上一页／下一页／完成问卷 |
| 评分任务 | 下一题／提交评分 |

错误文字直接说明修复动作，例如“请输入完整的 6 位数字编号”或“请选择评分后继续”。研究者提供的题干、选项、labels、同意书和自定义校验文字保持原文。

## 5. 页面布局合同

- 问卷内容最大宽度 `900px`；页面基础内边距从 `16px` 起，宽屏沿用 `3vw`，叠加设备安全区。
- 短选项在空间充足时可两列，长选项回到单列；保持协议的 DOM 顺序与读序。
- 普通页面使用文档流；题内可用 Grid，不用绝对坐标硬放控件。

| 运行模式 | 布局约束 |
| --- | --- |
| 逐题 `single` | 单题；所有选项／轴完整显示在答案区。题干必要时分页，选项空间不足时阻止继续。允许外层滚动访问导航，不裁切选项 |
| 自适应 `adaptive` | 按实际题卡高度组成屏幕页，宽屏可两列；每屏至少展示一题的完整内容，极小屏／长题可在题区滚动。文字输入独占屏幕页 |
| 图片／评分任务 | 独立 Canvas、状态区与底部槽位；开始前测量，运行中状态切换不改变几何。方向／视口变化按现有规则中断，不另设未经实现的像素阈值 |

## 7. 本地预览与修订记录

### 7.1 查看交互样张

交互样张为独立的原生 DOM 示例，不接入作答 API，不记录或持久化输入；无需构建或新增依赖。它用于检查外观与局部交互，不替代生产运行器、读屏软件或真机验收。

在仓库根目录运行以下命令，同时支持样张内的 Markdown 规范链接：

```sh
python3 -m http.server 3088 --bind 127.0.0.1 --directory docs
```

访问 [本地交互样张](http://127.0.0.1:3088/style-guide/)。浏览器对 Markdown 的展示方式取决于本地配置，也可直接在编辑器打开本文。

仅预览样张时可将目录改为 `docs/style-guide`：

```sh
python3 -m http.server 3088 --bind 127.0.0.1 --directory docs/style-guide
```

此时访问 [样张首页](http://127.0.0.1:3088/)，父目录中的规范链接不在服务范围内。也可直接用浏览器打开 `docs/style-guide/index.html`。
